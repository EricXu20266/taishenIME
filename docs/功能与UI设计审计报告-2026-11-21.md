# 泰深输入法（taishenIME）功能与 UI 设计审计报告

> 审计日期：2026-11-21
> 审计范围：`engine/` 核心引擎、`platform/windows/` TSF/IMM32 平台层与 Direct2D 自研 UI 框架（候选窗 / 工具栏 / 设置窗 / 语言栏 / 进程外渲染服务）

---

## 〇、总体评估（Executive Summary）

### 1. 项目亮点与工程优势

- **架构边界清晰**：采用「Rust 核心引擎（24 模块 / 81 FFI）+ C++17 双平台层（TSF + IMM32）+ `taishen-dict` 独立词库管线」三层解耦设计（[ARCHITECT.md](ARCHITECT.md)），FFI 边界全量 `ffi_guard!` 防止 panic 跨边界带崩宿主。
- **性能与沙箱演进扎实**：`.bin` 分片预编译索引将 54 万词库加载压至 ~700ms；近期针对 AppContainer（任务栏搜索/UWP）完成了异步 TSF 编辑会话（消除 `TF_ES_SYNC` 死锁）与 `taishen_server.exe` 进程外候选渲染服务（[taishen_server.cpp](../platform/windows/src/taishen_server.cpp)）。
- **质量门禁完善**：建立了 291 条分级用例的自动化考试系统（[exam.rs](../engine/examples/exam.rs)、[REPORT.md](modules/exam/REPORT.md)）及候选溯源机制（`Source` + `tier` + `reason` 位标）。

### 2. 审计发现的核心问题分布

本次对源码（`engine/` + `platform/windows/`）进行走查后，共定位 **21 项具体问题**（其中 **P0 级阻断/功能失效 7 项**、**P1 级严重交互/逻辑缺陷 8 项**、**P2 级视觉与体验改进 6 项**）：

## 一、UI 设计与自研窗体系统审计

### 1.1 候选窗（`CCandidateWindow`）渲染与交互

1. **[P0] 候选窗「字体名称」配置完全失效（死配置）**
   - **代码位置**：[candidate_window.cpp](../platform/windows/src/candidate_window.cpp#L88-L93)、[candidate_window.cpp](../platform/windows/src/candidate_window.cpp#L272-L318)、[ui_render.cpp](../platform/windows/src/ui_render.cpp#L207-L228)
   - **根因**：`CCandidateWindow::SetFont` 将 `m_fontFace` 存入 `CandidatePanel`，但 `CandidatePanel::Draw` 调用的 `r.DrawText(...)` 根本没有字体名参数；底层 `UIRenderer::Format` 硬编码了 `L"Microsoft YaHei"`。用户在设置页「基础 → 候选窗字体」或 `config.ini` 修改 `font_face` 均不会生效。

2. **[P0] 按 `↓`/`↑` 展开/收起多行候选时，候选窗向屏幕下方“步行漂移”**
   - **代码位置**：[candidate_window.cpp](../platform/windows/src/candidate_window.cpp#L434-L442)、[candidate_window.cpp](../platform/windows/src/candidate_window.cpp#L568-L665)
   - **根因**：`SetMultiRow`、`SetFont`、`SetLayout`、`SetLabelFormat`、`SetInlinePreedit` 在窗口可见时，调用了 `GetWindowRect(m_window.Hwnd(), &caret)` 把**候选窗自身矩形**当作光标矩形传给 `PositionWindow(caret)`。而 `PositionWindow` 内部计算 `int y = caretRect.bottom + 4;`，导致每次按 `↓` 展开或按 `↑` 收起多行面板，候选窗都会在当前底边下方再往下跳一个窗口高度。
   - **修复建议**：在 `CCandidateWindow` 中缓存最近一次 `UpdateState` 传入的真实 `m_lastCaretRect`，布局或展开态变化时基于 `m_lastCaretRect` 重新 `PositionWindow`。

3. **[P1] 候选词宽度按固定 `16px` 估算，未随字号缩放，且高分屏下最大宽度被物理像素截断**
   - **代码位置**：[candidate_window.cpp](../platform/windows/src/candidate_window.cpp#L111-L180)、[candidate_window.cpp](../platform/windows/src/candidate_window.cpp#L310-L318)
   - **根因**：
     - `ItemWidth` 按 `(label.size() * 16 + word.size() * 16 + 20) * scale` 估算宽度，**未乘 `fontScale (m_fontSize / 16.0f)`**。当用户将字号调大到 `22–32pt` 时，行高放大了，但列宽和序号区宽度（`label.size() * 16 * scale`）不变，导致序号与候选字重叠、长词右侧被裁切。
     - `word.size()` 是 UTF-16 码元数：英文候选（如 `application`）每个窄字母按 16px 算导致留白过大；而 Emoji 或拆字模式下的 CJK 扩展 B–I 汉字（UTF-16 代理对，`size() == 2`）1 个字被算成 2 个字宽。
     - `kMaxItemWidth = 240` 与窗口总宽上限 `if (width > 800) width = 800;`（[candidate_window.cpp](../platform/windows/src/candidate_window.cpp#L177-L179)）均未乘 DPI `scale` 与 `fontScale`，在 4K 200% 缩放屏幕下 800 物理像素仅合 400 DIP，9 候选横排时右侧被硬截断。
   - **修复建议**：直接用 `UIRenderer::MeasureText`（DirectWrite `IDWriteTextLayout`）测量真实文本宽高，并将 `kMaxItemWidth` 和最大窗口宽度按 `DpiScale() * fontScale` 换算。

4. **[P1] 进程外渲染服务（`taishen_server.exe`）候选窗无任何鼠标交互能力**
   - **代码位置**：[taishen_server.cpp](../platform/windows/src/taishen_server.cpp#L54-L65)、[render_ipc.h](../platform/windows/include/render_ipc.h)
   - **根因**：`taishen_server.exe` 中的 `CCandidateWindow` 未设置 `SetClickCallback`、`SetRightClickCallback`、`SetPageCallback`，IPC 协议也仅支持单向 `Show/Move/Hide/ReloadConfig`。在所有 AppContainer 应用（或开启 `use_server_render=1`）中，鼠标点击选词、右键置顶/降权/删词、滚轮翻页全部无响应。

5. **[P2] 候选窗缺少 `comment`（辅助提示/错音/拆字注音）独立渲染通道**
   - **代码位置**：[config_reader.h](../platform/windows/include/config_reader.h#L24)、[candidate_window.cpp](../platform/windows/src/candidate_window.cpp#L309-L319)
   - **现状**：主题配置与设置页「外观」都有「注释 (`theme_comment`)」色板，引擎也有错音提示（`mistake.rs`）和拆字反查注音，但 `CandidatePanel::Draw` 未拆分候选正文与注释，导致 `theme_comment` 色块成为无效配置。

### 1.2 设置窗体（`CSettingsWindow`）与自研控件库（`ui_*`）

6. **[P0] 数字输入框 `UIEdit::SetNumeric` 按键即夹紧导致无法输入，且破坏语音页浮点参数**
   - **代码位置**：[ui_edit.cpp](../platform/windows/src/ui_edit.cpp#L240-L249)、[ui_edit.cpp](../platform/windows/src/ui_edit.cpp#L318-L372)、[settings_window.cpp](../platform/windows/src/settings_window.cpp#L1126-L1137)
   - **根因**：
     - `UIEdit::OnChar` 和 `OnKeyDown` 每次按键都会调用 `NotifyChanged()` → 立即执行 `ClampNumeric()`。在「正文字号」（范围 `12–32`）中，用户清空后想输入 `16`：按下 `'1'` 的瞬间被 `ClampNumeric()` 夹紧改成 `"12"`，再按 `'6'` 变成 `"126"` 又被夹紧成 `"32"`，**用户无法通过键盘正常输入 12–32 之间的目标数字**。
     - 语音页的 3 个浮点数输入框（VAD 阈值 `0.005–0.20`、静音超时 `0.5–5.0`、最短语音 `0.3–2.0`）在 [BuildVoicePage](../platform/windows/src/settings_window.cpp#L1126-L1137) 中被错误调用了 `SetNumeric(1, 20)` / `SetNumeric(1, 50)`：既无法输入小数点 `.`，一旦点击该框再失焦，`ClampNumeric()` 用 `std::stoll` 把 `"0.02"` 截断为 `0` 并夹紧为 `"1"`，保存后 VAD 阈值被锁死在 `0.20` 上限。
   - **修复建议**：`ClampNumeric()` 仅在 `OnFocus(false)`（失焦）和 `CollectFromUI()` 时执行，不在 `NotifyChanged()` 逐键输入时执行；为 `UIEdit` 增加 `SetFloatNumeric(float min, float max, int decimals)` 或移除语音浮点框的整数 `SetNumeric`。

7. **[P0] 高分屏（>100% DPI）下设置窗体标题栏关闭按钮 `✕` 被画到窗口外且点击热区错位**
   - **代码位置**：[settings_window.cpp](../platform/windows/src/settings_window.cpp#L598-L650)
   - **根因**：`CSettingsWindow` 以 `dpiScale = true` 创建（640×520 DIP，在 150% DPI 下物理尺寸为 960×780），D2D 渲染目标已设置窗口 DPI（绘图坐标系为 0..640 DIP）。但 `CSettingsWindow::OnRender` 用 `GetClientRect` 拿到**物理宽度** `w = 960`，把关闭按钮 `✕` 画在 `D2D1::RectF(w - 46, 0, w - 8, 36)`（即 914..952 DIP），直接飞出 640 DIP 视口右侧，高分屏用户完全看不到关闭按钮；同时 `HandleMessage` 的 `WM_LBUTTONUP` 用物理像素 `y < kTitleBarH (36)` 判定，热区在高分屏下缩小了 1/scale。
   - **修复建议**：`OnRender` 和 `HandleMessage` 中将 `GetClientRect` 宽度除以 `DpiScale()` 转为逻辑坐标（DIP）。

8. **[P1] 弹出层（`UIComboBox` / `UIColorSwatch`）存在内存泄漏、销毁悬垂指针崩溃与超长下拉框截断**
   - **代码位置**：[ui_combobox.cpp](../platform/windows/src/ui_combobox.cpp#L134-L199)、[ui_colorpicker.cpp](../platform/windows/src/ui_colorpicker.cpp#L159-L197)
   - **根因**：
     - **内存泄漏**：`Collapse()` 中执行 `delete m_panel;`，但 [UIControl::~UIControl](../platform/windows/include/ui_control.h#L32) 不删除 `m_children`（树销毁需调 `DeleteControlTree`）。每次打开/关闭下拉框或色板，内部的 `ComboRow`（最多 27 个）或 `ColorCell`（128 个）全部泄漏。
     - **悬垂指针（UAF）**：`UIComboBox` 与 `UIColorSwatch` 未定义析构函数。当「高级 → 应用级配置」中某行的下拉框处于展开态时，用户点击该行 `×` 删除行（或切换页面/关闭窗口），控件被销毁但 `m_panel` 仍留在 `UIWindow::m_popups` 中，下次渲染或点击即触发 Use-After-Free。
     - **超长下拉框越界不可选**：「按键」页的「简/繁切换」下拉框含 27 项（`无` + `Ctrl+Shift+A~Z`），弹出面板高度 `27 × 30 + 4 = 814 DIP`，远超设置窗体总高 `520 DIP`。`ComboPanel` 无滚动条也不响应滚轮，`Ctrl+Shift+P` 之后的 10 个字母超出窗口底边被裁剪，完全无法用鼠标选到。

9. **[P1] `UIEdit` 鼠标点击光标定位失准 & 鼠标拖动选区功能失效**
   - **代码位置**：[ui_edit.cpp](../platform/windows/src/ui_edit.cpp#L112-L154)
   - **根因**：
     - `CharAt(int x)` 按 `(rel / Width()) * m_text.size()` 估算光标位置，分母用了整个输入框宽度 `Width()`（~300px）而非文本实际渲染宽度，导致输入短文本（如 `"16"`）时点击文字右侧空白处光标仍跳回第 0 位。
     - `OnMouseDown` 设置了 `m_selStart = SIZE_MAX; m_selAnchor = m_caret; m_dragging = true;`，但 `OnMouseMove` 只更新了 `m_caret = CharAt(x)`，**从未设置 `m_selStart = m_selAnchor`**，导致 `HasSelection()` 永远为 `false`，鼠标拖选文本完全无效。

10. **[P1] `UIRenderer::Brush` 缓存 Key 忽略 Alpha 通道 & `UITheme` `memcmp` 比较未初始化填充字节**
    - **代码位置**：[ui_render.cpp](../platform/windows/src/ui_render.cpp#L9-L17)、[ui_button.cpp](../platform/windows/src/ui_button.cpp#L20-L28)、[ui_window.cpp](../platform/windows/src/ui_window.cpp#L288-L292)
    - **根因**：
      - `ColorKey` 仅拼接 `(R<<16)|(G<<8)|B`，丢弃了 Alpha 通道。当半透明色与不透明色 RGB 相同时（例如 `UIButton` 主按钮禁用态 `bg = t.accent; bg.a *= 0.5f`），画刷缓存会发生碰撞互相覆盖。且 `UIButton` 的 `m_primary` 分支缺少 `UIState::Hover` 悬停反馈。
      - `UIThemeDark()` / `UIThemeLight()` 中 `UITheme t;` 未做 `{}` 零初始化，结构体对齐 padding 字节含栈随机值，`WM_SETTINGCHANGE` 使用 `memcmp(&t, &m_theme, sizeof(UITheme))` 存在未定义行为。

11. **[P2] 设置窗体缺乏单实例互斥保护**
    - **代码位置**：[banner_window.cpp](../platform/windows/src/banner_window.cpp#L384-L404)、[settings_window.cpp](../platform/windows/src/settings_window.cpp#L1502-L1521)
    - **根因**：每次点击工具栏「设置」都会 `std::thread(...).detach()` 新建一个 `CSettingsWindow` 线程，未加进程内原子锁或跨进程窗口激活（`FindWindowW(L"TaishenSettingsWindow", nullptr)` → `SetForegroundWindow`），连续点击会弹出多个设置窗口并发覆写 `config.ini`。

### 1.3 浮动工具栏（`CBannerWindow`）与系统语言栏（`CLangBarItemButton`）

12. **[P1] 浮动工具栏“去背景”不彻底，视觉上呈现为偏心的直角矩形块**
    - **代码位置**：[banner_window.cpp](../platform/windows/src/banner_window.cpp#L70-L107)、[ui_window.cpp](../platform/windows/src/ui_window.cpp#L365-L373)

    - **代码位置**：[banner_window.cpp](../platform/windows/src/banner_window.cpp#L30-L68)、[banner_window.cpp](../platform/windows/src/banner_window.cpp#L478-L489)

14. **[P2] 语言栏右键菜单缺少「打开设置」入口，且切换开关未持久化到 `config.ini`**
    - **代码位置**：[langbar_item.cpp](../platform/windows/src/langbar_item.cpp#L309-L369)
    - **根因**：`0.1.67` 停用系统托盘图标后，若用户点击工具栏「隐」关闭了浮动工具栏，任务栏语言栏的「中/英」右键菜单成为唯一控制入口。但该菜单：

## 二、功能与平台层链路审计

### 2.1 按键路由与平台兼容性缺陷

15. **[P0] 候选窗鼠标滚轮翻页方向反置，且滚动后画面不刷新（所见非所得）**
    - **代码位置**：[tsf_module.cpp](../platform/windows/src/tsf_module.cpp#L2788-L2794)、[imm32_ime.cpp](../platform/windows/src/imm32/imm32_ime.cpp#L322-L436)
    - **根因**：
      - `WM_MOUSEWHEEL` 向下滚动（下一页意图）传入的 `delta` 为 `-120`，向上滚动为 `+120`；而 `engine_page(int delta)` 约定 `> 0` 为向后翻页（下一页）、`< 0` 为向前翻页（上一页）。`SetPageCallback` 直接调用 `engine_page(delta)` 导致滚轮方向完全反置。
      - 更严重的是，`SetPageCallback` 内**只调用了 `RefreshState()`，漏掉了 `UpdateCandidateWindow()`**！滚轮滚动后引擎与 `m_candidates` 已翻到新页，但候选窗 UI 根本不重绘，此时按数字键选词会选出新页的词，与屏幕显示完全不符。
      - IMM32 兼容层（`imm32_ime.cpp`）则漏掉了 `CandWin().SetPageCallback(...)` 绑定。

16. **[P0] 默认中文标点模式下，「以词定字」（`[` / `]`）被全角标点分支提前截胡，功能完全不可达**
    - **代码位置**：[tsf_keyevent.cpp](../platform/windows/src/tsf_keyevent.cpp#L161-L162)、[tsf_keyevent.cpp](../platform/windows/src/tsf_keyevent.cpp#L527-L602)、[tsf_keyevent.cpp](../platform/windows/src/tsf_keyevent.cpp#L821-L835)
    - **根因**：在 `HandleKeyDown` 中，第 527 行的中文标点全角化分支（`MapFullWidthPunct` 将 `VK_OEM_4` `[` 映射为 `【`、`VK_OEM_6` `]` 映射为 `】`）排在第 822 行的「以词定字」之前，且注释写着“无论有无候选都处理——有候选时先上屏默认候选再打标点”。因此，在默认的中文标点模式（`ascii_punct == 0`）下，用户打字出现候选后按 `[` 或 `]`，会直接把第 1 个候选词整词上屏并追加 `【】`，**第 822 行的 `ReadEngineTakenChar` 永远不会被执行**！此外，第 822 行还漏判了 `g_keyBindings.pageBrackets && !shiftDown`。

17. **[P0] 「逗号 / 句号翻页」（`page_comma_period`）只吞键不翻页**
    - **代码位置**：[tsf_keyevent.cpp](../platform/windows/src/tsf_keyevent.cpp#L271-L275)、[tsf_keyevent.cpp](../platform/windows/src/tsf_keyevent.cpp#L495-L511)
    - **根因**：`ShouldEatKey`（第 271 行）检查了 `g_keyBindings.pageCommaPeriod` 并返回 `true`，但 `HandleKeyDown` 的翻页处理块（第 495–511 行）只检查了 `VK_PRIOR`、`VK_NEXT` 和 `plusMinus`，**完全遗漏了 `VK_OEM_COMMA` 与 `VK_OEM_PERIOD`**。导致用户在设置页勾选「逗号 / 句号」翻页后，按逗号/句号依然落入下方标点分支直接把首候选上屏（若开启英文标点，则按键被吞且无任何反应）。

18. **[P1] IMM32 兼容层与 TSF 主模块能力脱节**
    - **代码位置**：[imm32_ime.cpp](../platform/windows/src/imm32/imm32_ime.cpp#L205-L331)

### 2.2 核心引擎与输入体验审计（Rust Engine）

21. **[P0/P1] 引擎候选质量与全局状态隔离问题（基于 `exam` 报告与引擎代码审计）**
    - **代码位置**：[lib.rs](../engine/src/lib.rs)、[dictionary/mod.rs](../engine/src/dictionary/mod.rs)、[REPORT.md](modules/exam/REPORT.md)
    - **核心发现**：
      1. **[P0] 跨 `Engine` 实例的全局缓存污染与连续查询稳定性隐患**：[REPORT.md §五](modules/exam/REPORT.md#L141-L156) 证实 `npm` 单独测试首候选为 `npm(English)`，但在跑过 Combo 用例后新创建的 `Engine` 实例首候选变为 `女仆冥土小姐(Combo)`，说明 `dictionary` 层全局缓存跨实例泄漏了切分或候选状态；同时 [ARCHITECT.md §七](ARCHITECT.md#L275-L276) 记录连续查询 3000+ 次后存在偶发内存损坏崩溃。
      2. **[P1] 精确命中被模糊音（Fuzzy）和纠错（Correction）抢位**：当全拼已精确命中词库时（如 `nihao`、`lisi`、`zhangsan`、`fo`、`zei`、`suanfa`），`Fuzzy` 与 `Correction` 仍插入前 5 位甚至抢占第 1 位（`lisi` → `#1 历史(Fuzzy)`，`suanfa` → `#1 断法(Correction)`）。
      3. **[P1] 错拼/冗余尾字母被 `Combo`/`Sentence` 抢先强行组词**：如 `zhongguoo` `#1-#7` 全是「中国哦/中国噢/中姑婆」，把 `Correction` 纠回的「中国」挤到 `#8`；无意义连打 `qwer` / `sdfg` 仍生成 9 条 Combo 拼接词。
      4. **[P1] 简码/混输抢占与页宽耦合**：`sj` 仅产出 2 条时间候选导致「时间/世界/手机」不可达；`xian` 在 `page_size=5` 与 `9` 下第 5 位候选不一致（生成逻辑未与展示页宽解耦）。
      5. **[P2] 语音自管路径未闭环且错误无 UI 反馈**：未装泰深主程序时，设置页虽提供 Whisper 模型与硬件加速选择，但 `VoiceManager`（[voice_manager.cpp](../platform/windows/src/voice_manager.cpp#L173-L177)）尚未实现模型下载与 `whisper-server` 自启；点击工具栏「麦」启动失败时仅写日志，用户侧无任何视觉提示。
