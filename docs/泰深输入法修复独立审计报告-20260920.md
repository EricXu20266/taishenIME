
# 泰深输入法修复独立审计报告

**审计日期：2026-09-20**  
**审计范围：** `15b94f9`、`ae97c02`、`4390554` 相对 `c703493` 的修复  
**性质：** 独立只读静态审计；不替代真实微信/游戏宿主测试

## 一、结论

本轮修复消除了报告中的主要 P0 内存安全路径，并通过了 Rust 单元阶段、VS18 C++ clean build、smoke tests、资源校验和 Biome。独立审计仍发现 4 项 P1，集中在消息队列生命周期、异步词库代际、领域混拼预算和提交失败回滚。

## 二、确定的 P1

### P1-1 IMM32 待发送消息队列无界且缺少生命周期清理

位置：`platform/windows/src/imm32/imm32_ime.cpp` 的 `g_pendingMessages` 与 `ImeToAsciiEx`。

容量不足或调用方长期不消费时，按 HIMC 保存的队列持续增长；`ImeSelect(false)`、`ImeSetActiveContext(false)` 未清理对应队列，HIMC 重用可能收到旧消息。

建议：每个 HIMC 设置硬上限；在停用、销毁和上下文切换时清理；超限时保留关键消息并记录明确丢弃/失败状态。

### P1-2 异步词库加载缺少代际校验

位置：`engine/src/dictionary/mod.rs` 的异步领域/系统词库加载路径。

路径变化会启动新线程，但旧线程完成后没有校验对应的路径代际，可能把旧系统词库或旧领域数据提交到新路径状态。

建议：每次路径切换生成 generation token，后台完成时仅允许当前代提交 `DICT`、`PENDING_DOMAIN` 和 ready 状态。

### P1-3 领域混拼查询缺少内部扫描预算

位置：`engine/src/dictionary/mod.rs` 的 `domain_full_index` 与 `query_mixed`。

Engine 层的 4096 条排序预算发生在 `query_mixed` 返回之后，不能限制领域混拼查询自身的拼音桶扫描、结果追加和去重成本。

建议：在 `query_mixed` 内增加扫描上限、结果上限和去重预算；构建索引时对单桶设置合理上限，并保留精确/高频候选。

### P1-4 选词提交失败时已消费候选，缺少回滚/重试

位置：`engine/src/lib.rs::select_candidate`、`platform/windows/src/tsf_module.cpp` 的鼠标选词/`RunCompositionOp`、`platform/windows/src/imm32/imm32_ime.cpp` 的提交路径。

引擎选词会消费并 reset 状态；TSF 在无焦点上下文或编辑会话失败时可能不提交文本，IMM32 也未将 `PostMessageW` 失败纳入恢复状态。结果可能是候选已消失但文本未上屏。

建议：采用“待提交事务”或 peek/commit 两阶段接口；只有宿主提交成功后才消费候选；失败时保留文本并允许重试，同时记录事务 ID。
