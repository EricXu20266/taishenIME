## 二、第一目标：V4 打薄（DLL 瘦身 + Server 做厚）

### 2.1 目标定义

把 `taishen_ime.dll` 从「引擎 + UI + 网络栈 + 语音」的全量载体，降为**只做 TSF 契约适配与 IPC 转发的薄壳**；所有计算、渲染、语音、设置、托盘能力沉到 `taishen_server.exe`。

判据不是「体积数字」，而是**依赖清单**：打薄后的 `ime.dll` 不得出现 `d2d1`、`DWrite`、`reqwest`/`hyper`/`h2`，也不得链接 `taishen_engine`。

### 2.2 现状：ime.dll 里装了什么

`CMakeLists.txt:129-163` 的 `SOURCES` 清单（31 个 C++ 源 + 1 个 .rc）：

| 类别 | 源文件 | 打薄后归属 |
|:---|:---|:---|
| TSF 核心 | `dllmain.cpp`、`tsf_module.cpp`、`tsf_keyevent.cpp`、`tsf_composition.cpp`、`display_attributes.cpp` | **保留在 ime.dll** |
| 语言栏/图标 | `langbar_item.cpp` | **保留在 ime.dll** |
| 配置/日志/状态 | `config_reader.cpp`、`debug_log.cpp`、`app_state.cpp`、`dpi_util.cpp` | 保留（读配置的薄层） |
| IPC 客户端 | `ipc_render_client.cpp` | **保留在 ime.dll** |
| 候选窗渲染 | `candidate_window.cpp`、`banner_window.cpp` | 移入 server |
| 设置窗 | `settings_window.cpp` | 移入 server |
| UI 框架（13 个） | `ui_theme`、`ui_render`、`ui_control`、`ui_layout`、`ui_window`、`ui_label`、`ui_button`、`ui_checkbox`、`ui_edit`、`ui_combobox`、`ui_tab`、`ui_colorpicker`、`ui_scrollbar` | 移入 server |
| 语音 | `audio_capture.cpp`、`voice_manager.cpp` | 移入 server |
| 引擎桥 | `engine_bridge.cpp` | 移入 server（server 直接调 FFI） |

`server` 现有源文件（`CMakeLists.txt:360-371`）：`taishen_server`、`candidate_window`、`config_reader`、`debug_log`、`dpi_util`、`theme`、`ui_theme`、`ui_render`、`ui_control`、`ui_layout`、`ui_window`。

**缺口**：`settings_window`、`banner_window`、`audio_capture`、`voice_manager`，以及设置窗依赖的 `ui_label/button/checkbox/edit/combobox/tab/colorpicker/scrollbar`。

### 2.3 施工顺序（四步，每步可独立验证）

1. **补 server 能力**：把设置窗 + 工具栏 + 8 个 UI 控件 + 语音搬进 server 目标，server 内新增「打开设置窗」管道消息。此步完成后两套 UI 并存，`ime.dll` 不变，零风险。
2. **切默认**：`use_server_render = true`、`use_server_engine = true` 设为默认；V3 摘链接后进程内路径移除，`use_server_engine` 转为废弃兼容项（置 `0` 写警告日志）。此步开始所有宿主走新路径，**必须先在宿主矩阵冒烟**。
3. **摘链接**：从 `taishen_ime` / `taishen_ime_imm32` 目标移除 `taishen_engine`、`d2d1`、`dwrite` 与上表「移入 server」的全部源文件。此步是纯减法，编译期即可发现漏搬的符号。
4. **清残留**：`tsf_module.cpp` 拆为 `tsf_text_service` / `tsf_key_sink` / `tsf_edit_session` / `tsf_langbar` / `tsf_focus_caret`，物理删除托盘实现与空桩调用。

### 2.4 验收判据

| 判据 | 阈值 | 采集方式 |
|:---|:---|:---|
| `ime.dll` 依赖清单 | 无 `taishen_engine` / `d2d1` / `DWrite` / `reqwest` | `collect_baseline.py` 依赖扫描 |
| `ime.dll` 体积 | **< 1.2 MB**（<500 KB 作为冲刺目标） | 同上 |
| `server.exe` 体积 | < 6 MB（承接 UI 后会增长，须与 ime 降幅对冲） | 同上 |
| 宿主矩阵 | Edge / Win11 记事本 / VS Code / Office / 微信 / 32 位游戏 / 任务栏搜索（AppContainer）全部可输入 | 人工冒烟 |
| 考试基线 | 非缺陷组 ≥ 279/292 | `exam` |
| 确定性 | 两次进程候选哈希一致 | `collect_baseline.py` |

体积目标说明：<500 KB 偏激进。`ime.dll` 即使摘掉引擎与 UI，仍含 TSF 全栈、语言栏、COM 骨架与静态 CRT，1 MB 左右是现实下限。**以依赖清单为主判据，体积为辅。**

### 2.5 风险与回退

| 风险 | 征兆 | 保护 |
|:---|:---|:---|
| 老宿主走 server 后输入延迟或丢键 | 候选不出、组合区错乱 | 灰度期双路径可切；V4 摘链接后无进程内回退，应急回退请**降级安装旧版本**（`use_server_engine` 已废弃） |
| 设置窗搬到 server 后打不开 | 语言栏右键无响应 | 第 1 步完成后立即验证；失败则回退该步，不影响 ime |
| 32 位宿主（WOW6432Node）无法连 64 位 server | 32 位应用里输入法不出现 | 必须同时产出 32 位 server，或由 32 位 ime 直连引擎（保留降级） |
| `tsf_module.cpp` 拆分引入回归 | 焦点/编辑会话异常 | 拆分是纯移动，逐文件编译验证，不做逻辑改动 |

## 四、第三档：质量与生态（长期演进）

### 4.1 整句解码

- `sentence.rs:61` 的 `LN_RAW_TOTAL = 17.944` 一元常数项对每个词块独立扣除，导致「两字词 vs 两个单字」被人为拉开一个常数。改为二元条件概率（命中 TSLM 边时用 `ln P(w2|w1)`），并明确**边缺失时的平滑回退方案**——这是 v2.0 未交代的关键细节。
- 高冲突同音字双轨束搜索（在/再、的/得/地），打破 Top-9 束塌缩。
- 纯声母全简拼词图通道（当前 `sentence.rs:105` 限制伪段长度 4）。
- 目标从「40% → 70%」下调为**分阶段**：先做到 Top-1 ≥ 55%，再评估神经重排的投入产出。

### 4.2 易用性

- 模糊音 9 组改独立开关、默认关；`fuzzy.rs:50` 的子串替换改为音节边界替换（现状会产出 `zhhang`、`fal`）。
- 竖排候选、`-/=` 翻页、迁移预设。
- 设置页补「词库与数据」页、修复「恢复默认」误清 `app_*` 列表。
- 进程拾取器（`EnumWindows` 取 exe 名）。

### 4.3 平台契约与交付

- `ITfCompartment` / `ITfInputScope` / `ActivateEx dwFlags`（当前全仓 0 实现）。
- 安装迁 `%ProgramFiles%`、正式签名、`uiAccess="true"`、下线自签 Root CA。
- 修 `install.nsi:381/384` 硬编码 `VersionMajor=0` / `VersionMinor=2`，改为从 `/DVERSION` 拆解。

### 4.4 性能深水区

- 候选窗 `IDWriteTextLayout` 缓存（当前每键约 50–126 次创建销毁）——**打薄后这段代码在 server 内，应在搬迁时顺手重写，而不是先搬再改**。
- `bigram` 升 `TSBGRAM3` mmap。当前加载已降到 38 ms，优先级低于 v2.0 的定位；私有内存 39.7 MB 的主要构成需重新测（mmap 已占大头，堆增量近 0）。
- `zhongguorenmin` 峰值 19.73 ms 的尾延迟削峰（`zhongg` 过渡态）。
- `ActivateEx` 同步 SQLite/YAML：`radical_pinyin.dict.yaml` 改懒加载。

## 五、v2.0 断言抽验结果

对 v2.0 的 20 项关键断言逐条核对源码，结果如下。

### 5.1 属实（16 项）

DLL 体积、三大巨石行数、`TSBGRAM2` + `bincode` 堆反序列化、TSF 四类契约 0 实现、`LN_RAW_TOTAL`、`eprint!`、`fuzzy_enabled=true` 与子串替换缺陷、`use_server_*=false`、`page_minus_equal=false`、exam 306 条口径、CI 不跑测试、`selectedIndex=0` 硬编码、候选窗无页码、`process_key` 无视 cursor、数字透传不置标志、user_dict 7 处裸连（行号全对）。

### 5.2 偏差（3 项）

| v2.0 表述 | 实测 | 影响 |
|:---|:---|:---|
| 「新增 `move_cursor_char` 与 `set_cursor_edge` 并在 FFI 导出」 | `move_cursor` 已实现（`lib.rs:2302`）、`engine_move_cursor`/`engine_get_cursor` 已导出（`ffi.rs:583/595`）、Tab/Shift+Tab 已接入（`tsf_keyevent.cpp:735`） | WP1.4 被当成从零建设，工作量高估约一个数量级 |
| 「`engine_get_cursor_pos` 在 platform/windows 0 处调用」 | 符号名是 `engine_get_cursor`；「0 调用」的结论成立 | 名字错误，结论正确 |
| 「`SetSelectedIndex` 在 tsf_module 与 imm32 均 0 次调用」 | `taishen_server.cpp:994` 已在调用；缺的是引擎侧产出 | 渲染通路已存在，缺的是数据源 |

### 5.3 定性问题（1 项）

「约 400 行托盘死代码」——`tsf_module.cpp:1508` 起是托盘的完整实现（`g_trayInstances`、`WM_TRAYICON`、`RemoveTrayIcon()` 调用），属于「废弃但仍在编译」的功能，不是 `#if 0`。删除前须核调用链。

### 5.4 无法复核（4 项，二手引用）

`39.8 MB` 私有内存（实测 39.7–42.0 MB，基本吻合）、`20.79 ms` 峰值（实测 19.73 ms）、`cargo tree 239 行`、`50–126 次 DWrite 布局`（未逐次埋点，属静态计数推算）。

## 六、推进原则

1. **V4 是唯一的第一目标**。第二、三档的工作可在 V4 前后穿插，但不得阻塞 V4 收口。V4 未完成前，不新增任何依赖双轨并存的特性。
2. **每档以基线为门禁**。进入下一档前跑一次 `collect_baseline.py`，与 `docs/baseline/v0.1.90/baseline.json` 对比。体积、依赖、考试、确定性四项任一劣化即暂停。
3. **打分制取消**。v2.0 的五维百分比不再使用；「完成」= 对应判据在基线报告中为绿。
4. **词库改动一律回源**。任何 `resources/` 下的词库调整，必须在 `taishen-dict` 改 `curate/`，重建后 `sync_to_ime.py` 单向同步。
