## 二、各家设计细节

### 1. 微软拼音 — 系统级能力，零配置

Windows 系统级设置「允许我为每个应用使用不同的输入法」（设置 → 时间和语言 → 输入 → 高级键盘设置）：
这是 **TSF 框架的 per-window 能力**——每个应用记住上次使用的输入法及输入状态，切换应用即恢复。
微软拼音自身**没有任何** per-app 配置项，完全依赖系统能力。

**关键点**：per-window 记忆是 Windows TSF 的框架级默认行为，主流输入法都不需要自研——搜狗/QQ/微信/微软拼音在 Windows 上默认就有"每个程序记住中英文状态"。

### 2. 搜狗输入法 — 应用设置 + 兼容性黑名单（最丰富）

**用户可配置的应用设置**：属性设置 → 高级 → 应用设置，可添加特定程序，设置：
- 默认中英文模式
- 是否禁用输入法

**内置程序兼容性数据库**（changelog 持续维护，识别出的部分）：
- 终端类：MobaXterm 无法翻页、VS Code 控制台无法输入、cmd/powershell 系列
- 编辑器类：AutoCAD 候选框不显示、UE4Editor 候选框显示、Joplin 无法输入、WPS PPT 候选位置
- 游戏类：LOL 游戏中候选显示、CSGO 默认英文模式、穿越火线候选
- 浏览器类：msedge.exe QQ 空间候选丢失、Chrome 候选显示
- 其他：Clash 进程输入法同步失败、微软商店应用输入

**结论**：搜狗维护了一个**出厂自带的程序级兼容处理表**，这是输入法维护的主要工作量之一，也是差异化护城河。

### 3. QQ拼音 — 有应用设置但文档缺失

- 官网帮助中心（qq.pinyin.cn/help/）只有账号/等级/统计文档，无 per-app 功能文档
- 有「针对应用程序的特殊设置」（属性设置 → 高级）
- 版本 6.7.6500.400（2026-06 更新），仍在维护

### 4. 微信输入法 — 极简路线

- Windows 版更新日志：无 per-app 配置，仅「支持设置多种切换中英文的方式」
- 定位"简洁好用打字快"，靠系统 per-window 记忆兜底
- 最新 Windows 2.1.1（2026-07）

### 5. 雾凇（rime-ice，对照组）— declarative 配置文件

- `weasel.yaml` 的 `app_options`：按进程名配置 ascii_mode（双向）/ inline_preedit / vim_mode
- 语义：**初始状态**（首次进入应用时生效），用户手动切换后不被弹回
- 配置形式是 YAML 文本——比 GUI 更强大（可脚本化、可版本管理、可分享）
- 详见本会话前期分析（app_options 三层结构：前端配置 + ascii_composer 策略 + per-window 状态）

## 三、对泰深的启示

### ① per-window 记忆是 TSF 系统级默认能力
泰深早期用**全局引擎单例**（static ENGINE: Mutex），把所有程序的中英状态合并——反而抹掉了系统这个默认能力。
0.2.33 的 app_state 模块（按进程名记忆）是对齐主流的第一步，属于合理近似：
- 同进程多窗口共享状态符合直觉（浏览器多标签通常要一致状态）
- 不同进程隔离（终端英文、聊天中文互不干扰）

### ② 主流分两派
- **GUI 派**（搜狗/QQ）：应用设置放高级设置里，入口不显眼，但用户可操作
- **极简派**（微信/微软拼音）：无 per-app 配置，靠系统能力
- **declarative 派**（雾凇）：配置文件声明式，强大但门槛高

泰深当前 = 系统 per-window 记忆（对齐所有主流）+ 应用级配置（对齐搜狗/QQ）+ config.ini declarative（对齐雾凇）——组合已覆盖三家之长。

### ③ 兼容性黑名单是差异化护城河
搜狗 changelog 一半是程序兼容修复。泰深 app_options 是机制雏形，但**出厂程序表是空的**，需要积累：
- 终端类（cmd/powershell/wt/WindowsTerminal）→ 默认英文（当前只靠用户自己配 app_ascii）
- 已知问题程序 → inline_preedit 强制 / 特殊处理

### ④ 差距清单
| 差距 | 说明 | 优先级 |
|------|------|--------|
| 图形化入口 | 设置对话框只有进程名文本输入框，无结构化"程序→行为"管理 UI | P1 |
| 出厂程序兼容表 | 内置推荐配置（终端默认英文等），出厂即用 | P1 |
| vim_mode | Esc/Ctrl+C/Ctrl+[ 切 ASCII（雾凇 nvim-qt 场景） | P2 |
| 程序兼容 bug 库 | 后续实测发现的程序级问题，需要机制化记录 | P2 |

## 四、调研局限

- 搜狗帮助中心为 SPA 页面，正文无法抓取，应用设置的确切入口路径基于 changelog 与公开资料推断
- QQ拼音帮助中心无 per-app 功能文档
- 各输入法的实际行为（是否真正 per-window 记忆）为框架层面推断，未逐一装机验证
