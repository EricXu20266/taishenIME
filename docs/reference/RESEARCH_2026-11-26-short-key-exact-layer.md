# 短键（键长 ≤ 2）精确层特权设计分析（只分析、不动代码）

> 日期：2026-11-26 | 基准版本：`0.1.93`（`exam` 290/290 + 已知缺陷 11/11）
> 状态：调研与方案对比阶段（遵循「无数据不动手」原则，当前未改动任何排序代码）

---

## 一、问题机制定位（双层叠加）

当用户在单字母键（如 `l`）或 2 字母简拼键（如 `yg / zm / sh`）上连续选词 N 次后，发现排序行为与直觉有偏差时，背后实际由**两个不同层面的机制**共同作用：

1. **生成层（`engine/src/dictionary/mod.rs:4128-4203`，`query_with_split_meta`）的精确层先行**：
   - 规范学习写库时会将词归一到规范全拼（如 `le → 了`，拼音长 `2`；`yinggai → 应该`，拼音长 `7`）。
   - 查询短键 `key` 时，`user_index[key]` 仍按 `e.3 == key_len`（精确层）先出、`e.3 != key_len`（前缀扩展层）后出；精确层甚至包含了 `!is_user_active` 的休眠行（第 4147–4153 行），并打上 `pinyin: Some(key)` → `reason::EXACT_PINYIN`。
   - **历史遗留放大器**：旧版引擎（`4f0a650` 及之前）将大量未归一短别名写进了 `user_dict`（实测样本库自愈前 `5,149` 行中含 `len <= 2` 共 `226` 行，其中非完整音节 `len=1` 占 `1` 行、非完整 `len=2` 占 `29` 行，包含 107 天前的休眠行 `l → 脸 (freq=4)` 以及 `yg / gg / zm / yj / we / to` 等短键行）。在旧管线里，只要存在任意一条 `e.3 == key_len` 的条目，它就整层压过规范全拼写入的 `le → 了`。
   - **Phase 4B 自愈后现状**：自愈完成后同一副本中非完整 `len=1` 与 `len=2` 归零（`noncomp_len1 = 0, noncomp_len2 = 0`，仅余 `168` 条合法单音节全拼），历史别名污染已被源头清除。

2. **归约层（`engine/src/lib.rs:4567-4600` 与 `engine/src/ranking.rs`）的两种分化行为**：
   - 在 `0.1.93` 的 `ranking_v2` 下，单声母键（`len == 1 && !splits_clean`）会将 `EXACT_PINYIN` 与单字 `PREFIX_EXT` 同归 `Match::Shape (tier 2)`，按混合公式 `sys_prior + common_bonus + 150 * ln(1 + decay_eff)` 排序：
     - 这意味着 **0.1.93 中休眠的 `l → 脸` 已不再压过 `le → 了`**；
     - 但另一个真实边界浮出水面：单声母融合公式里 `user_bonus = 150 * ln(1 + decay_eff)` 在 `freq = 30` 时仅 `+557`，对 `sys_prior` 差距 >1500 的中低频单字（如 `lang → 浪`、`jie → 姐`）无法单靠连选 30 次冲上单字母首页（这是刻意防误触的平滑上限，而非精确层特权）。
   - 而在 **非完整 2 字母键（如 `we / to / zg`）** 上，若用户库仍存在活跃的 `e.3 == 2` 条目（如自造词、导入词或未自愈别名），它仍通过 `EXACT_PINYIN` 直接进入 `Dictionary` 精确层抢占 `#1/#2`（见下方反例实测）。

## 二、核心结论：短键（键长 ≤ 2）不能一刀切，必须先按音节合法性三分

`engine/tests/exam-cases.tsv` 共 301 条用例，其中 **键长 ≤ 2 共 111 条（占全库 36.9%）**，按语言学形态天然分成三类：

| 输入类别 | 判定条件 | 样例 | `exam` 用例数 | 精确层特权是否成立 |
|---|---|---|---:|---|
| **I 类：合法单音节完整全拼** | `splits_clean == true && len <= 2` | `a, e, o, ni, wo, de, le, bu, fa, ji, lu, si, fo, ai, an, ou, lv, ju, qu, xu, wu` | **34** | **必须成立**（精确单字必须绝对压过双字前缀补全） |
| **II 类：单声母键** | `len == 1 && !splits_clean` | `b, p, m, f, d, t, n, l, g, k, h, r, y, c, q, x, s, z, j, w` | **59** | **用户层不应有特权**（规范单字拼音均 ≥ 2 字节，仅 `common_dict` 特例 `l→了 / n→你 / m→没` 有 `len=1` 锚点） |
| **III 类：非完整 2 字母键** | `len == 2 && !splits_clean` | 复声母 `zh, ch, sh`；二字简拼 `nh, zg, bj, sj, yg, zm, we, to` | **18** | **对别名/休眠行不应有特权**；仅对「纯自造短码」（如 `ts→泰深`）有弱合理性 |

> 测试条件：全部在隔离临时副本中运行，预设 `meta.user_dict_heal_v1 = '1'` 以剥离自愈干扰、单独观察生成与排序链行为；`stale = 107 天前`，`fresh = 1 分钟前`。

| # | 场景（输入键 + 注入行） | `0.1.93` 实测结果 | 根因诊断 |

## 四、备选方案对比与 `exam` 回归面评估

先列出 `exam-cases.tsv` 中 **111 条短键（`len <= 2`）用例的分级分布**：
- **L1（21 条）**：全部为 `L1-A 全拼单字`（`a, e, de, wo, bu, le, si, fo, ai, an, ou, lv, lü, ju, qu, xu, lu, ji, wu` + `si @no_src=Completion`）。
- **L2（52 条）**：`L2-A 单声母首屏` 40 条（含 17 条 `@multi=0` 禁多字词约束）、`L2-B 双声母与两字简拼` 9 条（`zh/sh @no_src=Fuzzy,Combo`、`nh/zg/bj`）、`L2-D` 3 条（`sj`）。
- **L3（0 条）**：无 `len <= 2` 用例。
- **L4（10 条）**：`L4-B` 2 条（`fo/zh @no_src=Fuzzy`）、`L4-D` 4 条（`ji/de/wo/lu @no_src=Completion`）、`L4-F` 4 条（`ji/si/lu @no_src=Completion` + `lu !胪`）。
- **L5（28 条）**：`L5-D` 1 条（`de @no_src=Completion`）、`L5-E` 27 条（退化单字母与 `nn` 至少有候选）。

### 方案对比表

| 方案 | 具体做法 | 空库 `exam` 回归面 | 带真实/热词用户库回归面 | 优缺点评估 |
|---|---|---|---|---|
| **方案 A1：全 `len <= 2` 跨层按有效衰减分竞争** | 所有 `len <= 2` 不分合法音节，精确层与前缀层统一按 `user_decay_score` 跨层竞争 | 空库（无用户词）表面 0 掉分 | **高危：直接击穿 L1-A（至多 21 条）、L4-D/F（8 条）、L5-D（1 条）** —— 高频双字词（`nihao / women / fangan / yige`）会在 `ni/wo/fa/yi` 上全面压过单字；若未限制字数还会击穿 **L2-A `@multi=0`（17 条）** | **不推荐**。违反汉语全拼单音节精确匹配直觉 |
| **方案 A2：仅 `!splits_clean && len <= 2` 按有效衰减分跨层竞争** | 保留 I 类（合法单音节）全部精确层特权；仅在 II/III 类（单声母与非完整 2 键）的 `user_index` 中不再把 `e.3 == key_len` 独立置于 `exact_len` 前，改为合并后按 `effective_user_decay` 排序（且仅活跃词参与提权，单声母仍保持单字过滤） | **0 回归**（L1 96/96、L2 60/60、L3 13/13、L4 72/72、L5 60/60） | **正向收益**：彻底消除 N1–N4 在生成层与 `ranking_v2` 层的残留风险；仅当用户库存在低频 2 字母自造短码（如 `ts→泰深(2)`）时，需连用几次或显式置顶才能压过高衰减的常规简拼词 | **结构最干净的长期方案**；若要配合解决 N5（单声母高频自学习），需另行评估单声母权重系数，二者应解耦避免单声母首屏漂移 |
| **方案 B1：所有 `len <= 2` 取消精确层特权** | `query_with_split_meta` 在 `key.len() <= 2` 时直接跳过第一层精确段 | **灾难性回归**：**L1-A（21 条）大面积失守**，**L4-D/F（8 条）** 与 **L5-D（1 条）** `@no_src=Completion` / 单字首位大面积失败；若连 `common_index` 一并取消还会掉 **L2-A**（`l→了 / n→你 / m→没`） | 同左，所有常用单音节输入体验崩溃 | **明确否决** |
| **方案 B2：仅 `!splits_clean && len <= 2` 取消用户精确层特权** | 仅对非完整短键跳过 `user_index` 精确段，保留 `common_index` 与合法单音节 | **0 回归**（L1–L5 全绿） | 消除 N1–N4 风险；但会无条件剥夺纯自造 2 字母短码（如 `ts→泰深`）在 `user_index` 的精确命中，自造短码只能落回前缀层或依赖短语表 | 可行但不如 **方案 A2** 优雅（A2 用衰减分自然仲裁，不误伤高频自造短码） |
| **方案 C：维持现状** | 保持 `0.1.93` 现状（规范全拼学习 + Phase 4B 一次性带备份自愈 + 编码级右键置顶/降权 + `ranking_v2` 连续衰减） | **0 回归**（290/290 + 11/11） | 实测用户库自愈后 `noncomp_len1=0, noncomp_len2=0`，`l→了 #1`、`chongzhi→充值 #1`、`youjian→右键 #1` 全部恢复正常；仅残留「未来手工导入脏短别名」与「单声母中低频字提权幅度保守（N5）」两处边界 | **当前阶段最优选择**（零风险，先验证部署闭环后的真实体感） |

## 五、建议演进路径

1. **当前（`0.1.93` 部署后 1–2 周）**：采取 **方案 C（维持现状）**。真实用户库经 Phase 4B 自愈后，历史短键脏别名已彻底归零，配合编码级右键置顶可立即覆盖任意个人强偏好短键。
2. **后续若确需根治生成层短键特权**：仅落地 **方案 A2**（严格限定在 `!splits_clean && key.len() <= 2` 的 `user_index` 支路，绝不触碰 `splits_clean == true` 的合法单音节与 `common_index`），并在改码前先补充一组「带热词/休眠用户库」的短键专项回归测试（覆盖 P1–P5 与 N1–N4）。
3. **关于 N5（单声母选 N 次不提权的主观诉求）**：与「精确层特权」是两件独立的事。若真实使用中仍希望在单声母键上快速把某单字顶到首位，优先建议通过 **编码级右键置顶**（如仅置顶 `(l, 脸)` 而不影响 `lian`），而非盲目放大单声母无门槛学习权重——实测 `exam --user-db` 已证明全拼字频汇聚到单声母极易导致 `g/h/r/c/x/zh/ch` 首屏整体漂移。
