# 候选排序逻辑全景（2026-08-09 排查整理）

> 基于真实词库（system_dict 38.1 万 / domains 16.9 万 / common 538）实测复现。
> 对应 B-22/B-23/B-24（DEV-TRACKER）。

## 一、当前完整候选流程（query_all，engine/src/lib.rs）

### 第 1 步：特殊模式早退
`v` 符号 / `c` 计算器 / `u` 拆字 / `r` 数字大写 / `U` Unicode / 双拼 / 组词模式 —— 各自独立出候选，**不进入**拼音主流程。

### 第 2 步：日期简码早退
`rq/sj/xq/nl/dt/ts/rqzh/rqen` 精确命中 → 日期候选（用户词简拼命中时让位）。

### 第 3 步：主查询（按顺序追加，去重）
| 顺序 | 来源 | 函数 | 触发条件 |
|------|------|------|----------|
| 1 | 整词/前缀查询 | `query()` | 无条件 |
| 2 | 快捷短语 | 内置短语表 | 简码精确命中，插在用户词后 |
| 3 | 简拼补充 | `query_short()` | 无条件（声母索引） |
| 4 | 混合简拼（全拼前缀+声母后缀） | `query_mixed()` | 候选 < 40 |
| 5 | 缩写+全拼（声母前缀+全拼后缀） | `query_abbrev_full()` | 候选 < 40 |
| 6 | 模糊音变体 | `fuzzy_variants()` | **仅完整拼音** |
| 7 | ⚠️ 多音节切分拼接 | `phrase_guess()` | **candidates 为空**（无条件，BUG） |
| 8 | 拼写纠错（rime derive 规则） | `correction::spelling_variants` | 候选 < 5 |
| 9 | 多打字母容错 | `deletion_variants` | 候选 < 5 |
| 10 | 智能纠错（键位相邻） | `correction_variants` | **仅完整拼音** 且候选 < 40 |
| 11 | 错音错字提示 | `mistake::lookup` | 仅完整拼音 且候选 < 5 |
| 12 | 逐音节整词组合 | `query_combo()` | **仅非完整拼音** 且候选 < 40 |
| 13 | 逐音节拼接联想 | `combo_guess()` | **仅非完整拼音** 且候选 < 40 |
| 14 | 词库锚定拆分组词 | `phrase_group_guess()` | **仅非完整拼音** 且候选 < 40 |

### 第 4 步：收尾
15. 白话文长句过滤（>10 字丢弃，用户短语除外）
16. 截断到 max_pages 页
17. 自然语言日期追加（"日期/时间/年份"）
18. 英文混输追加（恒在末尾）
19. 置顶候选 pin_map 提到最前
20. `apply_long_word_filter`：长词从第 4 位起提前到第 4、5 位 ← **与用户需求冲突**
21. `apply_context_boost`：上下文搭配前置
22. `apply_domain_boost`：领域热度词前置 ← **抢位元凶**
23. `apply_sort_mode`：单字/长词分区（默认关）
24. 单字母输入（1 字符）只留单字候选

### query() 内部排序（词库层）
精确层（pinyin == key）：热用户词(7天内高频) → 温用户词(7天内) → **common 常用词(538)** → 过期用户词 → 领域词精确(key_len≥3，按热度) → system 系统词(词频降序) → 领域词追加
前缀层（pinyin 以 key 开头）：同样的 用户热 → 用户温 → common → 用户过期 → system → 领域

### 根因链

**繁体（B-22）**：词库构建无简繁归一化。
- system_dict.db：381,336 词中 **16,858 条**含繁体独有字
- domains.db：169,749 词中 **19,955 条**含繁体独有字
- 另有 GBK 乱码残留（紝/鐨/剉 等 mojibake，维基语料清洗产生）
- common.db（538 常用词）干净

**过度联想（B-23）**：
1. `phrase_guess` 无条件触发（无 is_full_pinyin 限制）——candidates 空时按音节 top 单字笛卡尔积拼接出「我们测是」。而 combo_guess / phrase_group_guess 都有 `!is_full_pinyin` 条件，**条件不一致是 bug**。
2. 领域词热度前置：sport 领域「我们是冠军」(womenshiguanjun) 前缀命中 + `apply_domain_boost` → 压过「我们」。
3. `apply_long_word_filter` 把 3-4 字短语从第 4 位起提前——与"输入 N 音节 → N 字词优先"的需求**方向相反**。

**优先级异常（B-24）**：与 B-23 同根，三级叠加（domain 前缀扩展 + domain_boost + long_word_filter）把常用双字词挤出前 5 位。

## 三、目标规则（Eric 2026-08-09 定义）

> 输入 N 个音节 → 前 4 位优先 N 字词，第 5 位起才放更长词/短句。不能过度联想。

| 输入 | 期望候选 |
|------|----------|
| wo（1 音节） | 1-4 位：我 / 握 / 窝 / 卧；第 5 位起：我国 / 我们… |
| women（2 音节） | 1-4 位：我们（2 字词优先）；第 5 位起：我们是冠军… |
| womenceshi（4 音节） | 1-4 位：我们测试（4 字词）；第 5 位起：更长的 |
| ceshi（2 音节） | 测试 / 侧室 / 侧视 / 测时…（2 字优先），第 5 位起：测试用例 |

## 四、修复方案（待 Eric 确认）

### A. 繁体归一化（B-22）
在**加载层**（`Dictionary::from_sqlite` / `load_domains_from_db` 循环）做繁→简转换：
- 复用 trad.rs 简→繁表**反向**做繁→简（词组优先，覆盖常用繁体），补常用繁体映射
- 转换后与同拼音已有简体词条**去重**（「我們」→「我们」与「我们」合并）
- GBK 乱码词条（U+E000 私人区 / 无简体映射的 mojibake 特征）**丢弃**
- 重建 system_dict.db.bin / 部署时自动重建

### B. 词长匹配排序（B-23/B-24 核心）
新增默认排序规则（取代 long_word_filter 的反向逻辑）：
- 输入 N 音节 → 候选按「字数 == N」稳定分区在前，N+1 次之，其余靠后
- 1 音节：单字占前 4 位，第 5 位起词组（当前 wo 已符合，保持）
- 2+ 音节：N 字词占前 4 位，第 5 位起放 N+1+ 字
- `apply_long_word_filter` 移除或反转（不再把长词提前）

### C. phrase_guess 限制（B-23）
- 加 `is_full_pinyin` 排除：完整拼音输入时（womenceshi 可完整切分）不触发音节拼接
- 或改为：仅当 candidates 空 **且** 词库锚定拆分（phrase_group_guess）也无果时才触发，且输出恒在末尾

### D. 领域词热度（B-24）
- `apply_domain_boost` 只对「字数 == 输入音节数」的词生效（热度加分不越级）
- domain 前缀扩展（非精确匹配）不再插到 system 精确词前
