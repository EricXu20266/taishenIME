## 二、选词逻辑专项对比

### 2.1 整句转换（语句级智能）
- **微软**：核心特色，源自哈工大"语句级智能输入"思想。连续输入整句拼音，不必人工分词，输入法自动分析校正为汉字。组字窗口最多 32 字，超出自动确认先输入部分。
- **搜狗**：云+本地智能组词，首屏准确率 95%+。
- **泰深现状**：词级输入，按词切分候选。无整句转换。

### 2.2 智能组词/简拼
- **搜狗**：支持简拼组词（首字母组合直接组词）、上下文关联候选。
- **谷歌**：智能组句引擎 + 主动下载用户习惯语言模型。
- **泰深现状**：已有联想补全（V0.4.1 combo_guess，≤4段递归拼接），简拼按音节/声母混合匹配。接近竞品水平，但无上下文（句内前文）参与选词。

### 2.3 纠错与模糊音
- **搜狗**：错音提示数据库（如"长chang相守"式注音纠错）、多拼/少拼/漏拼均可纠正。
- **谷歌**：典型规则 ng/gn 互换纠正（ting→tign 自动纠正）。
- **微软**：模糊音（z-zh/c-ch/s-sh 等）+ 智能模糊匹配候选明确标识。
- **泰深现状**：已有纠错规则表（SUFFIX_RULES 末字符类纠错 + spelling_variants）+ 模糊音开关。与谷歌/微软规则同源，无"错音提示数据库"式注音纠错。

### 2.4 候选排序策略
- **微软**：提供两种排序——单字优先 / 长词优先，用户可切换。
- **搜狗**：云词频 + 本地词频 + 用户词权重。
- **泰深现状**：常用词分层（common_dict）+ 用户词热/温两档学习（7天内≥3次压过常用词）。固定排序，无"单字/长词优先"切换。

### 2.5 以词定字
- **谷歌**：左右方括号 [ ] 选择当前候选词的开头/结尾字。
- **微软**：同样支持。
- **泰深现状**：无此功能。输入"谷歌"选词后想快速取"谷"字，只能删掉重打或翻页找单字。

### 2.6 特殊模式（U/V 模式）
- **搜狗 U**：笔画拆分（uhspn→朩）、汉字拆分（uniuniuniu→犇）、部首拼音拆分（氵+力→氻）、混合输入（upphu→虒）、笔画筛选 Tab。
- **微软 U**：笔画/部件/符号输入；**V**：数字转换、日期、时间、算式、Unicode/GB-18030 码位。
- **泰深现状**：已有 U 模式（radical.rs 部首拆字）+ V 模式（calculator.rs/datetime.rs/number.rs 大写金额）。已对齐主流水平。

### 2.7 自学习与自造词
- **微软**：自学习（用户每次修改都学习）+ 自造词工具（可设 2-8 字符快捷键，`ms → 微软（中国）有限公司）。
- **搜狗**：自定义短语（编码+候选位置+候选内容），上屏自动学词。
- **泰深现状**：用户词库自动学习（选词上屏），无自定义短语/快捷键造词功能。

## 四、结论

泰深输入法在**选词核心链路**（简拼、联想、纠错、模糊音、U/V 模式）已对齐主流水平，主要差距集中在：

1. **取字效率**——缺"以词定字"，这是谷歌/微软都有但被忽略的基础功能，成本最低收益最直接（P0-1）
2. **排序灵活度**——固定排序缺用户可选策略（P0-2）
3. **纠错深度**——错音提示库是搜狗特色，泰深规则表可扩展（P0-3）
4. **个性化**——自定义短语是高频需求，微软/搜狗都有（P1-4）

建议按 P0 → P1 → P2 顺序推进，P0 三项均可在引擎层低风险实现。
