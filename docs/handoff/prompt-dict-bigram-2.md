# 词库侧任务 · 第 2 轮：LLM 补长尾搭配（三道防线）

> 用法：新会话开新对话，把本文件全文作为第一条消息发过去。
> **前置：第 1 轮（prompt-dict-bigram-1.md）已完成并通过验收。**
> 产出：在既有搭配表基础上扩充长尾对，可用对 ≥ 50,000

---

## 为什么需要单独一轮

第 1 轮解决的是「有没有数据」。这一轮解决的是「数据够不够密」。

两者不能合并，原因有三：

1. **输入依赖不同**：本轮必须拿第 1 轮的产物当基线（并集、冲突取 min、覆盖率对比）。
   合并后 LLM 生成的数据混进统计结果里，出问题无法归因是哪一边的。
2. **验收标准不同**：第 1 轮看「覆盖对数」，本轮看「新增对里有多少被真实语境命中」。
3. **失败模式不同**：第 1 轮失败是「数据太少」，本轮失败是「数据是编的」。

## 背景

第 1 轮之后，`context_prior` 的 `count ≥ 2` 应有 3 万对以上（以第 1 轮报告为准）。

仍然存在的问题：**语料统计只覆盖「语料里真实出现过相邻」的组合**，
口语、新词、行业术语的搭配大量缺失。例如「这个」的后继词在语料里可能只有
几十个，但日常输入远不止。

LLM 在两类任务上强于统计：

- 「给一个前词，列出惯用后继词」——长尾覆盖明显更广
- 「判断这一对搭配是否自然」——比查询频次更懂语义合理性

但 LLM **不能**给绝对频次（它对「占语料 0.003%」没有校准能力），
所以档位必须受限，且必须用代码做强制校验。

## 目标

在既有 `count≥2` 的对数基础上，新增 20,000 条以上高质量搭配对，
使总量达到 50,000 以上，且**幻觉率（被白名单过滤掉的占比）低于 10%**。

## 第一步：读第 1 轮产物，建立基线

1. 读 `output/VERSION.json` 确认第 1 轮的版本号与 `bigram.db` 的 sha256。
2. 统计现有 `context_prior`：总行数、`count≥2` 对数、前词数、档位分布。
3. 找出**覆盖薄弱的前词**：从 `system_dict.db` 取词频 top 3000 的词，
   减去已经在前词集合里的那些，剩下的就是本轮要补的重点。
4. 把基线数据记进报告（后面验收要用）。

## 第二步：生成（分批，不要一次上千词）

对每个待补前词，让 LLM 输出 8-15 个惯用后继 + 档位标注。

**输入格式**（每批 30-50 个前词）：

```
前词：我们
后继（只允许常用词，按惯用程度标档）：
- 可以 | 4
- 需要 | 4
- 一起 | 3
...
```

**输出格式**：TSV `prev\tnext\ttier`，追加到 `tmp/llm_bigram_batch_N.tsv`

**档位口径**（与现有脚本一致，不要自创）：

| 档 | 含义 | 本轮允许 |
|----|------|---------|
| 2 | 一般搭配 | ✅ |
| 3 | 常见搭配 | ✅ |
| 4 | 极常见搭配 | ✅ |
| 5 | 很高频 | ❌ 只留给语料统计（需 16-39 次真实共现） |
| 6 | 最高频 | ❌ 只留给语料统计（≥40 次） |

**约束 LLM 输出**：
- 后继词必须是**真实存在的常用词**，不要造词、不要造短语
- 不要输出「前词 + 的/了/是」这类纯语法组合（现有脚本已有同类过滤，保持口径一致）
- 同一个前词不要重复输出

## 第三步：三道防线（写进脚本）

新建 `tools/merge_llm_bigram.py`，读 `tmp/llm_bigram_batch_*.tsv`，执行：

```python
# 防线 1：白名单（防幻觉）
vocab = load_vocab('output/system_dict.db')      # 全部词条集合
rows = [(p, n, t) for (p, n, t) in rows if p in vocab and n in vocab]

# 防线 2：档位封顶
rows = [(p, n, min(t, 4)) for (p, n, t) in rows]

# 防线 3：去重取 min（同一对只留最小档位）
best = {}
for p, n, t in rows:
    best[(p, n)] = min(best.get((p, n), 99), t)
```

然后与第 1 轮的 `bigram.db` **并集**：

- 同一对两边都有 → 取 min（保守，宁可低估）
- 只有 LLM 有 → 用 LLM 档位
- 只有语料有 → 保持原档位

输出新的 `context_prior` 到 `output/bigram.db`。

**必须打印统计**：输入行数 / 白名单过滤掉多少 / 最终新增多少 / 幻觉率。

## 第四步：验收

| 项 | 标准 |
|----|------|
| `verify_build.py` | 通过 |
| `count≥2` 总对数 | ≥ 50,000 |
| 幻觉率（白名单过滤占比） | < 10%（超过说明生成质量不合格，要改 prompt 重来而不是放宽防线） |
| 档位 5-6 的数量 | **不得增加**（新增对只能落在 2-4） |
| 抽样 30 条新增对 | 人工确认语义合理，无「优先级→县级」这类语法通但非词的组合 |
| `probe_context` | 真实案例提升数 > 第 1 轮的结果（会打印每例 off/on 位次差） |

## 第五步：如果验收不达标

**不要硬凑数据过关。** 按以下顺序判断：

1. 幻觉率 > 10% → 生成 prompt 有问题（约束不够严），改 prompt 重生成，**不要放宽防线**
2. 新增对数量少 → 前词清单太小，扩大 top N 或换领域
3. `probe_context` 提升数没变化 → 说明新增的对不在真实输入路径上，
   回报实测数据，**停下来等决策**，不要继续灌数据
