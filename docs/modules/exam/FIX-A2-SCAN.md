# FIX-A2-SCAN：group_rec A2 阶段声母段扫描区间

> 日期：2026-11-18
> 范围：`engine/src/dictionary/mod.rs`（`group_rec` 的 A2 阶段 + 新增 `combo_seg_ranges`）
> 结论：L3 6/13 → 8/13，总通过 242 → 244；L1/L2/L4/L5 全部持平基线。

---

## 一、根因

`group_rec` 的 A2 阶段用 `full_index.range(seg..)` 找「seg 能读成哪个词」的候选，
前提是 `seg` 必须是目标拼音的**字符串前缀**。

纯声母段成立（`j` 是 `jie` 的前缀），但**声母缩写段不成立**：

```
seg = "shj"     →  区间 [shj, shk)
目标拼音 = "shijie"（世界）
字典序： "shijie" < "shj"   （第 3 字符 i < j）
```

区间从 `shj` 开始向后扫，`shijie` 在其**前面**，永远扫不到。「你好世界」因此
进不了候选（`nihaoshj` 修复前前 9 无此词）。

`nhshijie` 同理：`nh` 与 `nihaoshijie` 的字典序关系不成立，A2 给不出「你好」。

---

## 二、改动

### 2.1 新增 `combo_seg_ranges`

把声母缩写段摊回完整音节序列，逐个音节生成窄区间：

1. **贪婪切出完整音节前缀** `prefix`（只在音节长度 ≥2 时前进，
   避免把声母假象——`shj` 的 `s`——当成完整音节吃掉）；
2. 剩余 `rest` 取首声母组 `g`（zh/ch/sh 两字符，其余首字符）；
3. 枚举音节表里所有以 `g` 开头的完整音节 `syl`，生成区间
   `[prefix+syl+下一段首字符, prefix+syl+该字符+1)`；
4. `rest` 为空时退化为原窄区间 `[seg, seg 末字符+1)`。

```
shj  → prefix="", rest="shj", g="sh", tail="j"
       syl=shi → [shij, shik)  ← 世界 shijie 在此
       syl=she → [shej, shek)  ← 设计 sheji 在此
nhshijie → nh → g="n", tail="h"
       syl=ni  → [nih, nii)    ← 你好 nihao 在此
```

区间只缩小扫描范围，**正确性仍由 `combo_match` 保证**（不删任何现有过滤）。

### 2.2 双段扫描（关键）

A2 现在分两段：

| 段 | 条件 | 作用 |
|---|---|---|
| 第一段 | 总是先跑 | 原逻辑原样保留：`[seg, seg 末字符+1)` + 扫描上限 1200 |
| 第二段 | 第一段扫不到候选，且满足放宽门槛 | `combo_seg_ranges` 多区间 + 词频排名 |

**第一段一个字都没改**（包括 1200 这个上限）——实测改动上限或排序会让你
为「heshenm → 和什么」这类既有正确路径回归。

放宽门槛（三条同时满足）：

- `seg.len() <= 4`：放宽服务的是「几个声母拼成的缩写」，更长的串是没打完的拼音；
- `is_consonant_initials(seg)`：整段纯辅音声母（`shj` / `nh`），含元音的
  `hesh` 不是缩写而是音节内部片段；
- `at_edge`：首段任意长度；末段要求 ≥3 字符（2 字符末段 `nm` 在变体串里会
  命出「你们」，挤掉正确拆分）。

### 2.3 多义消歧

`shj` 天然多义（`sha+ji` / `she+ji` / `shi+jie`）。按区间遍历顺序取前 N 个会让
字典序靠前的「杀机」挤掉高频的「世界」，因此：

- **末段**：每区间取 8 条命中，合并后按词频降序（世界 3814 第一）；
- **首段**：按「常用词优先 + 词频」定探索顺序（「你好」词频 2405 低于
  「南海」2791，纯词频会让南海系列先占满 DFS 输出预算）；
- **首段名额**：`take_n + 5`（首段无前文可打分，需要更宽的候选池；
  末段已有前文，保持 `take_n`）。

## 三、扫描上限调整依据

| 常量 | 值 | 依据 |
|---|---|---|
| `A2_NARROW_SCAN_LIMIT` | 1200 | 修复前原值，**不动**。实测调到 2400 会让 `hes` 区间多扫出命中，`heshenm` 回归 2 条 |
| `A2_SCAN_LIMIT`（放宽段总量） | 2400 | `shj` 放宽后实测扫 929 条即取到「世界」（世界在第一声母区间内），2400 是 2.5 倍余量 |
| `A2_PER_RANGE_HITS` | 8 | `shij` 区间内按字典序为 shiji / shijian / shijiang / shijiao / **shijie**，「世界」排第 5；取 4 会漏掉它，取 8 覆盖常见组合 |
| `A2_RELAX_MAX_SEG_LEN` | 4 | 放宽只处理缩写段（shj=3 / nh=2）；`shenm`（5）由第一段窄区间负责 |

## 七、为什么停在这里（已知边界）

1. **`nihaoshj @no_src=Combo` 与 `nihaoshj 你好世界 5` 互相矛盾**：
   「你好世界」只能由 Combo 产出（词库无此整词），所以「前 5 有你好世界」
   与「前 5 无 Combo」不可能同时成立。该条不是本次能修的，属用例设计问题。
2. **首段按最长声母组消费**：只枚举 `sh`（不枚举子声母 `s` + `hj` 路径）。
   后者要求第二音节以 h 开头、第三音节以 j 开头（如 sa+hao+ji），语义无意义，
   旧实现同样覆盖不到。
3. **放开更长的段会回归**：`shenm`（5 字符）走放宽能让「和什么」多一条来源，
   但同时会让变体串的伪组合占满 DFS 输出预算，净效果是 L1 掉 2 条。
   当前门槛（≤4 + 纯辅音 + 位置）是实测能保住 L1 的边界。
