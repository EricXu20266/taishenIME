# 输入法考试工具升级设计

> 目标：每次引擎/词库改动后，用一条命令跑完整分级考试，输出可对比的通过率。
> 现状：`engine/examples/exam.rs` 只能断言「期望词在第几位」，86 行用例、9 个扁平分组。

---

## 一、现状的三个硬缺口

| 缺口 | 后果 |
|---|---|
| 只能正向断言「某词在第几位」 | 无法检出「不该出现的词」——垃圾词组、错别字、生僻字抢位 |
| 不暴露候选来源 | 无法验证「纠错词不抢占正常词」「错误拼音不该强行组词」 |
| 用例扁平无分级 | 无法回答「简拼质量如何」「长句适用性如何」，只有总通过率 |

第三点对应你说的问题：**错误拼音无法组成适用词时，不该强行组词**。现在的考试工具从结构上就检不出来——它只会问「期望词在不在前 N」，不会问「这里根本不该有 Combo 候选」。

---

## 二、分级框架

| 等级 | 考核内容 | 通过标准 |
|---|---|---|
| **L1 全拼** | 单字 / 双字词 / 长词 / 长句 | 单字命中率、词首位率、长句成句率 |
| **L2 简拼** | 单声母首屏质量 / 2-5 字词 / 长句（软考核） | 首屏必须全是常用字，词首位率 |
| **L3 混拼** | 全拼+简拼混合 / 组词适用性 | 命中率 + 切分合理性 |
| **L4 纠错与联想** | 纠错命中 / 纠错不抢占 / 不强行组词 / 联想排位 | 全部为硬断言 |
| **L5 边界场景** | 多音字、ü、儿化、隔音、标点、中英混、繁简、翻页 | 分项 |

## 四、断言语法设计（向后兼容）

保持「一行一断言」，第 2 列用前缀区分类型：

| 第 2 列写法 | 含义 |
|---|---|
| `期望词` | 正向：该词在 max_rank 内（现有行为） |
| `!词1,词2` | 反向：这些词不得出现在前 N |
| `>词A>词B` | 顺序：A 必须排在 B 前 |
| `@src=Dictionary` | 类型：前 N 全是该来源 |
| `@no_src=Correction,Combo` | 类型：前 N 不得有这些来源 |
| `@multi=0` | 前 N 全为单字（多字词数 = 0） |
| `@multi>0` | 前 N 至少 1 个多字词 |
| `@count<=5` | 候选总数 ≤ 5（防灌满） |
| `@count>=3` | 候选总数 ≥ 3（防过少） |

分组名即等级：`[L4-C 无意义串不强行组词]`。

### 统计输出改造

现在的输出是「分组通过率」，升级为：

```
L1 全拼        单字 92% (12/13)  双字词 88% (7/8)  长句 60% (3/5)
L2 简拼        首屏 75% (6/8)    2-5字词 90% (9/10)
L3 混拼        85% (11/13)
L4 纠错        命中 100%  不抢占 40%  不强行组词 20%   ← 问题集中区
L5 边界        95%
```

每条 FAIL 输出可复现的候选列表（含来源标记）。

## 六、优先级建议

先做 **L4**——它检出的问题最严重（垃圾词组、纠错抢占），而且当前工具完全检不出来。

L4 六条断言一旦跑起来，能立刻量化「强行组词造成多少垃圾」这个问题。这与你前面发现的「组词池 96% 是垃圾」是同一个病根。
