# 输入法考试工具规范（SPEC）

> 适用范围：`engine/examples/exam.rs` 与 `engine/tests/exam-cases.tsv`。
> 目标：引擎/词库每次改动后，一条命令跑完分级考试，输出可对比的通过率与可复现的失败候选。

---

## 一、命令与退出码

```bash
# 全量考试
cargo run --release --manifest-path engine/Cargo.toml --example exam

# 指定用例 / 词库 / 候选窗宽
... --example exam -- --cases engine/tests/exam-cases.tsv --dict resources/system_dict.db --top 9

# 关闭前缀补全（全局）
... --example exam -- --no-completion

# 打印候选+来源（写用例时校准，不跑断言）
... --example exam -- --dump zei ji nihao
```

退出码：`0` 通过（已知缺陷组的 FAIL 不算失败）；`1` 存在非已知缺陷的 FAIL；`2` 环境问题（词库缺失/未就绪/用例文件读不到/语法错误）。

---

## 二、用例文件格式

TSV，`#` 开头为注释，`[分组名]` 开启新分组。

```
拼音<TAB>断言<TAB>范围<TAB>备注
```

| 列 | 含义 | 缺省 |
|---|---|---|
| 1 | 输入串（可为空串，用于空输入退化测试） | 必填 |
| 2 | 断言（见下表） | 必填 |
| 3 | 断言生效范围 N（前 N 个候选），从 1 起 | 1 |
| 4 | 备注；也承载开关（见下） | 空 |

备注里的开关：

- `completion=off`：该条关闭前缀补全。
- `traditional=on`：该条开启繁体输出。

---

## 三、断言语法（最终版）

| 写法 | 语义 | 判定细节 |
|---|---|---|
| `期望词` | 正向：该词出现在前 N | 找不到即 FAIL |
| `!词1,词2` | 反向：这些词不得出现在前 N | 命中任一即 FAIL |
| `>词A>词B>词C` | 顺序：A 在 B 前、B 在 C 前 | 任一缺失即 FAIL；任一超出 N 即 FAIL |
| `@src=Dictionary` | 前 N 候选全部来自该来源 | 前 N 至少要有 1 个候选，否则 FAIL |
| `@has_src=Correction` | 前 N 至少一个来自该来源 | 空窗口 FAIL |
| `@no_src=Correction,Combo` | 前 N 不得有这些来源 | 命中任一即 FAIL |
| `@multi=0` / `@multi>=1` / `@multi<=2` | 前 N 的多字词数量约束 | 字数按汉字计（CJK 区） |
| `@count<=N` / `@count>=N` | 候选总数约束 | 用 `candidate_count()`（当前页内数量） |
| `@page_stable=N` | 候选窗宽稳定性 | 以 `page_size=N` 重跑，前 N 与宽窗前 N 逐项一致 |

比较符统一支持 `=`、`>=`、`<=`、`>`、`<`，纯数字等同 `=`。

向后兼容：第 2 列不以 `!` / `>` / `@` 开头时按正向词断言处理，旧用例零改动可跑。

## 四、来源名（稳定契约）

`engine/src/lib.rs` 的 `Source::as_str()` 是对外唯一命名来源：

```
Dictionary / Phrase / Datetime / English / Emoji / Correction
Combo / Fuzzy / Mode / Voice / Sentence / Completion
```

**这些字符串一旦定下不得修改**——用例文件直接按它们写断言，改名等于让全量用例失效。
新增 `Source` 变体时必须同步补 `as_str()` 分支，否则编译期 match 会报错（有意为之）。

按索引取来源用 `Engine::candidate_source_name(i)`（页内索引，与 `candidate(i)` 同语义）。
FFI 侧可选导出 `engine_get_candidate_source_name(index, buf, len)`。
注意与旧的 `engine_get_candidate_source` 区分：后者按**词**反查词库层级（1=用户词/2=专业词库/3=系统词），粒度不同，保持不变。

---

## 五、分级口径

分组名格式：`[L{级别}-{子类} 说明]`，例如 `[L4-C 无意义串不强行组词]`。
统计时按分组名首个 `-` 之前的部分聚合（`L4-C ...` → `L4`）。

| 级别 | 考核内容 |
|---|---|
| L1 | 全拼：单字、双字词、长词长句、叠词、儿化隔音 |
| L2 | 简拼：单声母首屏、双声母、2-5 字简拼、简拼质量与不灌满 |
| L3 | 混拼：全拼+简拼、声母段拼接、组词适用性 |
| L4 | 纠错与联想：纠错命中、纠错不抢占、无意义串不组词、联想排位、英文不误判 |
| L5 | 边界：标点数字、中英混、姓名专名、网络新词、术语、翻页、窗宽、繁体、退化输入 |

### 已知缺陷口径

分组名含「已知缺陷」的用例：

- FAIL **不计入**总计、**不影响**退出码；
- 单独输出「已知缺陷 X/Y 通过」与 FAIL 明细；
- 用途：如实量化当前引擎缺陷（如补全灌满候选），同时让 CI 的退出码只反映回归。

判定依据是**分组名**，不是备注。新增已知缺陷组必须显式带这四个字。

---

## 六、输出约定

1. 分级统计：每个级别一行通过率；含已知缺陷的级别追加一行「不含已知缺陷」。
2. 失败明细分两段：「失败明细（不计已知缺陷）」与「已知缺陷 FAIL 明细」。
3. 每条失败带可复现信息：

```
[L4-B 纠错不抢占] nihao @no_src=Fuzzy → 范围 5，命中禁用来源: #2 利好(Fuzzy), #3 理好(Fuzzy)
      实际: #1 你好(Dictionary)  #2 利好(Fuzzy)  #3 理好(Fuzzy)  ...
```

4. 候选文本取 `candidate_display(i)`（与宿主显示一致，含繁体转换与英文大小写），来源取 `candidate_source_name(i)`。

---

## 七、维护规则

1. **不许为了让用例通过而放宽断言**。期望值写「合理位置」，不是「当前实际位置」。
2. **不许删旧用例**。换分组可以，断言原文保留。
3. **新增来源变体必须补 `as_str()`**，并在 SPEC 的来源名清单更新。
4. **新增断言类型**必须同时更新本文件第三节和 `parse_assertion`。
5. 用例校准用 `--dump`，不要靠猜：先看真实候选与来源，再写应然断言。
6. 已知缺陷组的用例一旦被修复，FAIL 会变 PASS，届时把它移出已知缺陷组，转为普通回归。

---

## 八、已知测量局限

- **用例顺序效应**：同一进程内连续跑大量用例时，前面的输入会影响后面的候选组成
  （实测 `npm` 单独跑为 `#1 npm(English)`，在完整用例中变为 `#2`，`#1` 出现 Combo 词）。
  引擎侧疑似存在跨 Engine 实例的全局缓存，属引擎缺陷，待单独排查。
  当前用例顺序固定，结果可复现；调整用例顺序后请重跑基线。
- **时间型候选**：`sj` 等简码会出 `Datetime`（如 `22:35`），断言不受时间影响，但失败明细中的文本会随运行时刻变化。
- **翻页场景（51）**：当前工具只取首页，用 `@count>=9` 近似表达「不丢词」，未真正翻页。
- **`@page_stable` 揭示的真实差异**：`xian` 在 page_size 5 与 9 下第 5 位不同（西安 vs 现在），
  说明候选组成受页宽影响，属引擎缺陷。
