## 二、垃圾候选的三个来源（实测定位）

用 `TAISHEN_GROUP_DEBUG=1` + `--dump` 抓到每条候选的 `errs/segs/score/common`：

| 来源 | 产出示例 | 生成逻辑 |
|---|---|---|
| `phrase_group_guess` | 我爱你妈（我爱你+妈）、你好杀及、你哈世界 | 词库锚定拆段，每段命中一个词条就拼接 |
| `combo_guess` | 你好是就、你是接、儿童用 | 逐音节取单字笛卡尔积拼接 |
| `query_combo`（冷僻整词） | 我阿尼玛（我+阿尼玛）、你护士节（你+护士节） | 词库存在冷僻词条，被当成切分锚点 |

第三类是最隐蔽的一类：**词库里有「阿尼玛」「护士节」「豪商」这些真实词条**，拆组把它们当锚点，组合出似真似假的短句。

**结论 1：词频无法区分两组。**

- `system_dict.frequency` 对单字记录的是「字频」（该字在任何语境下都计数），与多字词的「词频」不可比。
- 任何形如 `min(段频) ≥ N` 或 `sum ≥ N` 的阈值，都会把「你好杀及」（min=2405）判得比「点击使用」（min=2171）更可靠。

## 四、实际采用的阈值：段结构（语义锚判据）

既然频次与搭配都不可用，剩下的唯一可区分信号是**段结构**：

| 候选 | 段结构 | 判定 |
|---|---|---|
| 点击使用 | 点击(2字) + 使用(2字) | 两段都是词 |
| 电机使用 | 电机(2) + 使用(2) | 两段都是词 |
| 我爱你妈 | 我爱你(3) + 妈(1) | 含实义单字「妈」 |
| 你好杀及 | 你好(2) + 杀(1) + 及(1) | 含实义单字 |
| 你哈世界 | 你(1) + 哈(1) + 世界(2) | 含实义单字「哈」 |

落地的判据（`combo_seg_is_anchor`）：

1. **段是 ≥2 字的词** → 最强语义锚，接受；
2. **段是结构助词/连词/介词/副词**（的/在/和/是/就/没/不/也/都/很…）→ 接受。理由：真实短语必然含功能字（「这个|我们|的」「和|什么」），一刀切要求全多字会误伤；
3. **段是代词单字**（我/你/他/这/那）→ 满足其一即接受：
   - 组合 ≥3 段（「你|们|在」是正常代词链）；
   - 组合里有一个 2 字基本词（「他|使用」）。
   2 段且另一段是 3 字以上派生词/专名时拦掉（「我|阿尼玛」「你|护士节」）。**注意不能用常用词表判定**——实测「阿尼玛」「护士节」也在 `common_words` 里，只能用段字数区分。

明确排除：语气词（吗/吧/呢/啊）、动词后缀（了/着/过）、实义单字（妈/杀/及/哈/接/好）。

语气词必须排除的理由：它们与名词单字同频段（吗 3638 / 妈 3111 / 码 2679），频次无法区分；但在组合里它们不承担连接作用，只是句末添头。用户打 `ma` 要的「妈/马/码/吗」作为独立候选已经给到，不需要靠语气词拼四字串。

## 五、为什么选它而不是方案 A/B/C

题目给的三个方案都以「词频」为轴（每段 ≥N / N-1 段命中常用词 / 总分 ≥N），但第三节的数据表明 **词频轴本身不成立**——单字与多字处在不同的计量口径上。所以改用「段是否为词」这个结构性事实：它不依赖语料统计口径，且与「组词是否读得通」直接对应。

## 六、实施细节

改动只在 `engine/src/dictionary/mod.rs`，两处：

1. `group_rec` 收集结果时多记一列 `all_multi`（每段是否都满足锚判据）；
2. `phrase_group_guess` 在排序后、截断前 `retain`；`build_combo_words` 在每段候选生成后过滤。

**生效范围限定为输入 ≥8 字符**（`input.len() >= 8`）。原因：短串（`nimzai` 6、`heshenm` 6）的正确候选「你们在」「和什么」是 combo_guess 拼出的**边界候选**（基线里「你们在」正好排第 9，用例范围 9）——语义门槛一旦削短候选池，lib.rs 的插入位次随之变化，会把这类候选挤出前 9。这是实测到的回归，不是推测。

## 八、L3 剩余 7 条为什么没修好

| 用例 | 原因 |
|---|---|
| `woainima` 我们爱你吗 | 候选池里没有这个词：`wo` 段只取到单字「我」，要出「我们」需给每个音节段开放多字前缀补全，会引发组合爆炸 |
| `nihaoshj` 你好世界 | 「世界」的简拼段 `shj` 走 `combo_match`，但 A2 阶段的词库扫描范围用字符串区间 `["shj","shk")` 划定，而 `shijie` 的拼音不以 `shj` 起头（`i` < `j`），永远扫不到 |
| `nhshijie` 你好世界 | 同上：`nh` 段的区间 `["nh","ni")` 覆盖不到 `nihao` |
| `nihaoshj` / `nhshijie` @no_src=Combo | 剩余 Combo 是「你好是」「你是解饿」——「是」在白名单（真实短语「这个我们的」需要「的」类功能字），拦不掉 |
| `moshoushijzhenhaow` @no_src=Combo | 「没收世纪真好玩」三段全是多字词（没收/世纪/真好玩），段结构判据无从下手；真正的问题是搭配不成立，而 bigram 表无此条 |
| `erty` @no_src=Combo | 「儿童用」由 combo_guess 拼出，er+t+y 三段里「用」是功能字，「儿/童」是实义字——但该输入只有 4 字符，落在 ≥8 字符的门槛豁免区 |

**按要求停下来，不硬上坏阈值。** 后面三条（nihaoshj/nhshijie 的期望词、moshoushijzhenhaow）不是阈值问题，是两处结构性缺陷：

1. **A2 阶段声母段的扫描区间选错**（用 `seg` 自身做字符串区间起点，而简拼段不是任何拼音的字符串前缀）；
2. **Combo 候选池大小影响插入位次**（lib.rs 的 `prepend` / `combo_start` 分支随 `candidates.len()` 切换），任何过滤都会间接改动排序。

修这两处要动 `group_rec` 的范围划定和 lib.rs 的插入策略，超出「加一道语义门槛」的范围，本轮不做。

## 十、遗留与后续

1. 修 `group_rec` A2 阶段的范围划定：声母缩写段（`nh`/`shj`）应按首字母划定扫描区间，而非用 `seg` 本身做字符串前缀——这是「你好世界」进不了候选的直接原因。
2. 把 Combo 插入位次与候选池大小解耦（lib.rs 的 `prepend` 分支），否则任何过滤都会间接改动排序。
3. `jintiantqhz` 类输入的候选不足，需要给非末段音节的「多字前缀补全」设限开放。
4. bigram.db 覆盖不足（385992 条，连「点击|使用」都没有），若要靠搭配做语义判据，需先补语料。
