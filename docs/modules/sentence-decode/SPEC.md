# SPEC — 整句解码（长输入）

> 模块：engine（Rust 核心，`engine/src/sentence.rs`）
> 日期：2026-11-16（初版 + 同日审计修复）
> 状态：已实现，接入普通输入流与组词整句层

---

## 一、需求

连续输入长串拼音时，输出「整句最优词序列」作为候选，允许用户一次上屏整段，
同时保留所有词级候选。

**要解决的失败模式**（均为修复前实测）：

| 输入 | 修复前 | 期望 |
|------|--------|------|
| `nimenjigezaizheli` | 你们几个**再者里** | 你们几个在这里 |
| `nimenjigerenzaizheli` | 你们几个**认栽**这里 | 你们几个人在这里 |
| `nimenjigezaizheliganshenme` | 无候选 | 你们几个在这里干什么 |

**根因**：原实现靠 DFS 拆段、按「段数少」优先、段数上限 5、输出预算 512 条先到先得、
输入上限 24 字符、最终还无条件删除 >10 字候选。长句的正确路径经常根本没被探索到。

**不做**：

- 缩写输入（`nimjige` 的 `m` 代表「们」）——需要词首字母槽，当前只做音节级容错
- 双拼管线接入（`query_all_shuangpin` 暂不调用整句解码）
- 跨句上下文建模

## 二、接口

```rust
// engine/src/sentence.rs
pub fn decode(input: &str, prev: Option<&str>, limit: usize) -> Vec<String>

// engine/src/dictionary/mod.rs
pub fn span_candidates(pinyin: &str, limit: usize) -> Vec<(String, u32, u8)>
pub fn clear_span_cache()
```

`decode` 返回得分最高的前 `limit` 条整句（文本去重）；`prev` 是前文已上屏的最后一个词，
参与句首搭配打分。含英文/数字或读不通的输入返回空。

## 三、启用条件

接入点在 `Engine::apply_sentence_candidates`：

1. 输入长度 ≥ 8 字符
2. 纯 ASCII 小写字母
3. 至少 3 个音节
4. 不是英文词典里的精确单词（`international` / `database` 这类不猜中文）
5. 整段音节数 ≤ 30（超长按粘贴处理，不猜）

不满足任一条件直接返回，不消耗查询。

## 四、算法

### 4.1 音节切分

```
segmentations(input)
  ├─ segment_exact：每个位置必须是合法音节，按音节长优先展开，最多 8 条
  └─ segment_tolerant：精确切分完全走不通时才启用
       支持单字符替换（打错）、音节删除（漏打）、音节插入（多打）
       单处编辑代价 5，总编辑 ≤ 3；每段近邻音节只试 3 个
       递归带节点预算，防长串指数展开
```

音节边界歧义（`xian` = `xian` / `xi+an`）保留多条切分路径，
分别跑 Viterbi 后合并排序。

### 4.2 词图与打分

```
格子[i][k] = 从第 i 个音节起、连续 k 个音节（k ≤ 8）在完整拼音索引中命中的词
             （用户 / 常用 / 系统 / 领域四层，每格最多 6 个）
```

单词语义得分（`step_score`）：

```
ln(freq + 1) − LN_TOTAL × WORD_COUNT_BETA + WORD_BONUS
  − 低频扣分（freq < 300 时 1.5）
  + 用户词加成（layer = 用户时 1.0）
  + BIGRAM_W × ln(1 + 搭配档位)
```

路径得分 = 前驱得分 + 当前词得分 − 编辑代价（每处 5.0）。

| 常量 | 值 | 作用 |
|------|----|------|
| `LN_TOTAL` | 19.37 | 词库总词频对数（ln 2.59e8） |
| `WORD_COUNT_BETA` | 0.6 | 每个词的词数惩罚；1.0 会让书面语词频过度偏好拆碎单字 |
| `WORD_BONUS` | 2.0 | 成词奖励，偏好成词而非高频单字一路拆 |
| `LOW_FREQ_CUTOFF` / `PENALTY` | 300 / 1.5 | 书面语低频专名在口语长句里几乎不该出现 |
| `BIGRAM_W` | 0.6 | 搭配权重，按 `ln(1+档位)` 计入 |
| `USER_BONUS` | 1.0 | 仅用户词层；常用词不再逐词加成 |
| `BEAM_WIDTH` | 8 | 每个位置保留的部分路径数 |
| `MAX_WORD_SYLLABLES` | 8 | 一个词最多覆盖的音节数 |
| `SPAN_TAKE` | 6 | 每个格子最多取几个词 |

**为什么常用词不逐词加成**：按词给的加成会让拆碎的单字路径吃双份——
「吃 + 反」两个常用字各加一次，反而压过「吃饭」。实测网格搜索 20 例，
`β=0.6 + bonus=2.0 + 不按词加成` 首位命中最高。

### 4.3 重建与输出

`Node { start, text, score, back }`，每个位置保留束宽内的节点；
结束后按 `back` 回溯出完整词序列。同文本去重，取前 `limit` 条。

## 五、数据源：`span_candidates`

整句格子专用查询，与词级 `query()` 的区别：

1. **常用词表第三字段是人工 rank，不是词频**。直接当词频用会把「在 / 再 / 载」拉平，
   同音字分不出高下。实现上统一折算成系统层同名词的真实词频
2. **候选先按词频排序再截断**，避免常用词表里排名靠后的高频词被挤出格子
3. 返回 `(词, 得分词频, 层级)`；层级语义：`0` 系统 / `1` 常用 / `2` 用户 / `3` 领域，
   仅用户层参与 `USER_BONUS`
4. **跨按键缓存**：格子按输入前缀复用；词库换入、领域合并、用户词删除/切换/清空时
   整体清空（审计 P0/P1——否则启动初期用内置词库算出的结果会被长期复用）

## 六、接入普通输入流

```rust
// lib.rs::query_all 尾部
self.apply_sentence_candidates(&mut candidates, &mut cand_seen, &norm_str);
```

- 整句候选倒序插到候选最前，最多 3 条
- 同文本已存在时**只挪位置、不改来源**——「中国」这类普通词条不能因为整句
  也给出同一文本就被标成 `Source::Sentence`（否则跳过学习与上下文记录）
- `Source::Sentence` 豁免 `MAX_CAND_WORD_LEN = 10` 的长句过滤
- 整句不写 `last_committed`、不写搭配学习（审计 P1：否则每次整句写一条
  「前词 → 25 字串」垃圾搭配，下一次整句的前文变成整句本身）

## 七、组词整句层

`dictionary::sentence_guess(input, prev_word, limit)` 复用同一套拆组递归，
用于组词模式把剩余音节整体转换：

- 透传前文已选词参与 bigram（选完「魔兽」后「世界」应压过「时间」）
- 两道质量门槛：**零错**（不靠单错变体硬凑）+ **常用词过半**
- 组词候选只取 1 条，避免挤占后面的短词

| 输入长度 | 累计耗时 |
|---------|---------|
| 13 字符 | ~85ms |
| 20 字符 | ~90ms |
| 25 字符 | ~300ms |

已改为 `bigram_scores` 批量取锁。

## 九、已知限制

- **同音词歧义**仍受词库词频偏差影响：`womenxiangquchifan` 首位是「我们想曲吃饭」，
  正确解在第 3。需要更高质量的口语搭配统计
- **缩写输入不支持**：`nimjige` 会读成「你米格人」
- **双拼未接入**：双拼候选走 `query_all_shuangpin`，不出整句
- **格子缓存满时整体清空**：可换 LRU
- 整句插入仍晚于置顶/降权（长句场景置顶词极少命中，暂按现状）
