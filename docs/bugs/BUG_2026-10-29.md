# Bug 修复记录 — 2026-10-29

## BUG-2026-10-29-01: 小键盘 + 输出成 `=`（归一化丢掉 Shift 语义）

**现象**：中文模式按小键盘 `+`，上屏 `=`。

**根因链**（`platform/windows/src/tsf_keyevent.cpp`）：
1. `NormalizeKeypad()` 把 `VK_ADD` 归一为 `VK_OEM_PLUS`；
2. `MapFullWidthPunct(VK_OEM_PLUS, shift)` 按 Shift 状态取字符：无 Shift → `=`；
3. 小键盘 `+` 从来不产生 Shift，于是恒定走 `=` 分支。

**同类问题（同一次归一化丢失字符语义）**：
| 原始键 | 归一结果 | 错误行为 |
|--------|----------|----------|
| `VK_ADD` | `VK_OEM_PLUS` | 输出 `=`（应为 `+`） |
| `VK_MULTIPLY` | `'8'` | 有候选时选第 8 个候选；计算器模式进数字 `8` 而非 `*` |
| `VK_ADD`/`VK_SUBTRACT` | `OEM_PLUS`/`OEM_MINUS` | 有候选时被当成翻页键（`pageMinusEqual`） |
| `VK_NUMPAD0-9` | `'0'-'9'` | 有候选时被当成选词键 |
| `VK_DECIMAL`/`VK_SEPARATOR` | `OEM_PERIOD`/`OEM_COMMA` | 开启逗号句号翻页时被当成翻页 |

**修复**：
- 新增 `IsKeypadKey(rawVk)`（判断是否小键盘键）与 `KeypadShiftEquivalent(rawVk)`
  （`VK_ADD`/`VK_MULTIPLY` 在主键盘需 Shift 才产出同一字符）；
- `HandleKeyDown` / `ShouldEatKey` 增加 `rawVk` 参数（保留原始键码），
  `tsf_module.cpp` 两处与 `imm32/imm32_ime.cpp` 一处调用点传入原始 `wParam`/`uVirKey`；
- HandleKeyDown 顶部统一 `shiftDown = 真实 Shift || KeypadShiftEquivalent(rawVk)`；
- 小键盘符号与数字不参与候选选词 / `+/-` 翻页 / 逗号句号翻页；
- 计算器与数字大写模式先按 `rawVk` 直取小键盘字符（修 `VK_MULTIPLY` → `*`）。

**验证**：`platform/windows/test/test_ascii_mode.cpp` 新增 STEP8/STEP9 ——
小键盘 `+`→`+`、`*`→`*`、`-`→`-`；小键盘数字 5 不选候选且透传；英文模式 `+/-` 不翻页。
`test_ascii_mode.exe` 全绿。

**教训**：把「物理键」归一成「等价键」是有损操作。归一必须同时携带被折叠的
修饰键语义（Shift / 小键盘身份），否则后续所有按修饰键分支的映射都会算错。

## BUG-2026-10-29-02: 新增的中英状态托盘图标被系统塞进溢出区

**现象**：0.1.46 新增的「中/英」状态托盘图标（`71a1d46`）出现在 Windows 溢出面板里，
而泰深品牌图标一直直接显示在任务栏。

**根因**：两个图标用了各自独立的 `NOTIFYICONDATA.guidItem`。品牌图标的 GUID 已存在
于 Shell 的 `NotifyIconSettings`（用户固定过），新 GUID 是全新图标 → Shell 默认归入溢出区。

**为什么不能程序化强制固定**：`Shell_NotifyIcon` 没有「固定到任务栏」参数；唯一相关的是
未文档化的 `HKCU\Control Panel\NotifyIconSettings\<hash>.IsPromoted`，键名由 Shell 内部
哈希生成，需要重启 explorer 才生效，且系统更新可能失效——不作为方案。

**修复**：合并为一个图标。
- 删除 `kTrayModeGuid`、`GetModeTrayIcon()`、`m_modeTrayAdded`；
- 品牌图标 `GetTaishenIcon` 本身已按中/英绘制两种视觉（中文「泰」/ 英文「t ENG」），
  tooltip 追加当前模式；
- 左键切中英、右键弹菜单（原独立状态图标的行为）；
- 清理 `InitTrayIcon` / `ReAddTrayIcon` / `UpdateTrayIconFor` / `RemoveTrayIcon` /
  `OnTrayCmdBroadcast` 中的双图标分支。

**效果**：托盘只剩一个图标，沿用用户已固定的品牌图标 GUID，位置不变。

**遗留**（不在本次范围）：`test_banner_window.exe` STEP1 失败——测试期望
`IsEnabled()` 默认 `true`，而 `CBannerWindow` 构造函数是 `m_enabled(false)`，
与本次改动无关，需要产品侧确认默认值后再对齐测试。

## BUG-2026-10-29-03: `pageMinusEqual` 在中文模式下是死配置（翻页被标点抢先）

**现象**：设置页勾选「减号 / 等号」翻页后，中文模式按 `+`/`-` 仍然直接上屏标点，不翻页。

**根因**：`HandleKeyDown` 里中文标点分支（`MapFullWidthPunct`）位于翻页判定之前，
`+`/`-` 属于标点映射表，必然先被吃掉并 `return true`，后面的翻页分支永远到不了。
只有英文模式或 `ascii_punct=1` 时翻页才生效。

**修复**：把翻页判定整体前移到标点映射之前，仅当「有候选 且 该键被配置为翻页键」时
先尝试翻页；翻不动（无更多页）再往下走标点。同时把 `+/-` 与小键盘 `+/-` 拆成两个
独立开关（`page_minus_equal` / `page_numpad`），默认全关。

**验证**：`test_ascii_mode.exe` STEP10 —— 勾选后 `+` 被吞且不提交标点（进入翻页分支）；
取消勾选后 `+` 末字符为 `=`。测试内置词库只有 4 个候选，无法断言真实换页，
真实翻页需人工验证。

## 附：托盘点击语义变更

原 `TrayWndProc` 用 `wParam == 2` 区分状态图标（左键切中英），其余走品牌图标
（左右键都弹菜单）。合并后统一为「左键切中英、右键弹菜单」，`wParam` 不再参与判断，
避免沿用失效的 id 分支。
