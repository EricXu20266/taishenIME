## 二、任务 1 判据：`RankKey` 新增用户频次维度

### 1. 维度位置与定义

在 `Attestation` 新增字段 `pub user_freq: u32`（默认 `0`），在 `RankKey`（12 元组 → 13 元组）中置于 **`user_tier` 之后、`segment_count` 之前**：

```text
0: explicit_rank
1: demoted
2: pref_rank
3: rare_rank
4: effective_match_tier
5: extent_rank
6: user_tier
7: user_freq_rank   <-- 新增：u32::MAX.saturating_sub(self.user_freq)
8: segment_count
9: context_rank
10: common_order
11: freq_rank
12: form_rank
```

### 2. 关键门控：`user_freq` 仅在 `user_boosted == true` 时生效

```rust
let user_freq = if user_boosted { eff_user_freq } else { 0 };
```

**为什么必须门控在 `user_boosted` 上（而不是所有 `is_user`）？**
- 当 `user_boosted == true`（`user_tier == 0`）：多条被提权的用户词之间按 `eff_user_freq` 降序排列。
  - `anz`：`安装(92)` 与 `按照(17)` 均在 `user_tier == 0`，`92 > 17` → **#1 安装、#2 按照**。
  - `fu`：`副(5)` 与 `服(5)` 均在 `user_tier == 0`，频次相等时自然落到后续维度（`common_order` / `freq`）→ **#1 副、#2 服**（均在首屏）。
- 当 `user_boosted == false`（`user_tier == 1` 或 `3`）：`user_freq = 0`，`user_freq_rank = u32::MAX`，**完全退化为中性**。
  - 若不门控，则 `ji` 下未提权的 `级(9)` 会在 `user_tier == 1` 内压过 `及(1)`，直接破坏实机护栏 `ji → 及`；`shi` 下未提权的 `式(14)` 也会在 `user_tier == 1` 内反超 `时(4)/使(2)/事(3)`。
- `effective_match_tier`（第 4 维）仍在 `user_tier`（第 6 维）与 `user_freq_rank`（第 7 维）之前，因此用户频次**绝不会压过更精确的匹配层**（如 `ces` 下 3 字别名不会反超 2 字精确词）。
- 未学习词 `user_freq = 0` → `u32::MAX`，对干净引擎排序零影响。

## 四、任务 3 判据：组词模式候选预算可扩展

### 1. 现状问题

`engine/src/lib.rs` `Mode::Compose`（约 2475 行）：
- `let budget = self.page_size * 3;`（`page_size=5` 时仅 15 条）
- Step 0（首单字）+ Step 1（整句 + 多音节前缀词，每级 `PER_STEP_TAKE=4`）占用前段，Step 2（当前音节单字兜底）被 `cands.len() >= budget` 截断在第 15 条。
- 结果：系统词库中排第 27 的「服」在 `fule` 组词态下永远无法翻页到达。

### 2. 推荐方案

- **多音节前缀词阶段（Step 1）**：保持现有 `word_budget = self.page_size * 3` 与 `PER_STEP_TAKE = 4` 不变，确保组词首屏（第 1 页）仍严格优先展示「首单字 + 整句 + 能消费多个音节的整词」，**首屏行为零退化**。
- **当前音节单字兜底阶段（Step 2）**：解除 `self.page_size * 3` 截断，将 `fallback_words` 中的当前音节单字全部追加进候选列表（上限放宽至 `fallback_words` 自身长度，或 `(self.page_size * self.max_pages).max(100)`），使任意排名的同音单字均可通过翻页触达。
