## 二、拼音依据（多音字按词义取音）

- **神祇 → shenqi**：祇在「地神」义读 qí，不取「只」义的 zhǐ。同音词「神奇/神气/神器」共存，故频次给 650 而非 800，避免压制更常用的同音词。
- **攥紧 / 攥拳 → zuanjin / zuanquan**：攥只有 zuàn 一读（握义），不取 cuán。
- **背景下 → beijingxia**：jing 取「景」的 jǐng；xia 取方位义 xià。
- **时代课题 → shidaiketi**：四音节全拼，逐字取常用读音。
- **先进制造业 → xianjinzhizaoye**：制造取 zhìzào，不取 zhī。
- **安全水平 → anquanshuiping**：水平取 shuǐpíng。
- **呦呦 → youyou**：拟声词，yōu yōu。
- **懵逼 → mengbi**：网络口语，mēng bī。
- **异地恋 → yidilian**、**瘦脸 → shoulian**、**按错 → ancuo**、**按错了 → ancuole**：均为单音字直取。

格式与 `curate/extra_words.txt` 现有条目一致：`词<TAB>连写拼音<TAB>频次`，不带音节分隔符。
pipeline 融合阶段会把频次按基线补偿抬到 2300+ 档（实测写入 700 → 落库 2392），这是既有机制，非手工写错。

## 四、引擎侧修正：日期简码不再独占候选池

`ts` 此前只出时间戳（`datetime_candidates` 命中即 `publish + return`），
导致「提升/同时」这类高频简拼**完全打不出来**——不是词库缺词。

- 位置：`engine/src/lib.rs` `query_all()`
- 改动：日期候选改为 `datetime_seed`，在**全部排序与过滤完成后**统一插到候选池首部，中文候选追加其后，可翻页取
- 保留原有优先级：日期仍排第 1 位；用户词简拼（`user_short_hit`）仍优先于日期
- 一次返工：第一版在候选构建阶段就插入，被「短语插到索引 0」的既有逻辑顶掉（`sj` 只剩手机、时间候选消失，`test_datetime_sj_precedes_phrase` FAIL）。改为末尾统一前置后，`sj` 恢复为 `01:27 / 01:27:43 / 手机`，`rq`/`xq`/`nl`/`dt` 日期候选均保持在前。

配套词库动作：把 `提升 tisheng` 插入 `curate/common_dict.txt`（`同时` 之前）。
简拼系门禁 `short_keep` 对纯声母串只放行常用词，`提升` 进常用词表后才能在 `ts` 下出现。
