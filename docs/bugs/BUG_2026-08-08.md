# Bug 修复记录 — 2026-08-08

## BUG-2026-08-08-01: 中文模式无组合时打不出标点（第三次修复，根因在提交链路）

**现象**：中文模式下，光标在文本中（无拼音组合）直接按标点键（如逗号/句号），
标点完全打不出来。修过 2 次（0.2.27/0.2.28 标点映射表、V0.3.x 无条件全角化+
有候选先上屏），均只改了映射表/吞键逻辑，未触及提交链路，故复发。

**根因**：`CTsfComposition::CommitComposition` 在 `m_pComposition == nullptr`
（无活跃组合）时直接 `return S_OK` 放弃提交。但按键链路是：

```
ShouldEatKey（吞键 true）
  → HandleKeyDown（committed="，"）
    → OnKeyDown → RunCompositionOp(Op::Commit, "，")
      → CommitComposition → 无组合 → return S_OK（什么都不做）
```

键被吞了，标点却没上屏 → 用户看到"打不出标点"。
最常见的触发场景：打完一句话，光标在句尾，按逗号/句号——此时没有任何组合。

前两次修复路径：
- 0.2.27/0.2.28（02b5e58）：标点映射表对齐 rime half_shape + 复选/配对引号
- V0.3.x（266f326）：ShouldEatKey/HandleKeyDown 改为标点无条件全角化
两者都只保证"按键被正确识别为标点并生成 committed"，但提交端无组合时
直接放弃的问题始终存在。

**修复**（tsf_composition.cpp）：`CommitComposition` 无组合但有非空文本时，
先 `StartComposition(ec, pic, "")` 建空组合，再走原有替换+结束流程；
空文本（ESC 撤销）仍保持 `return S_OK`。

**验证**：
- 构建通过（VS18 NMake + MSVC 14.51）
- test_tsf_load / test_config_reader / test_banner_window 通过
- test_ascii_mode STEP4 失败为既有问题（英文模式切走后引擎拼音未清，
  与本次修复无关，另行跟踪）
- DLL 已部署至 %LOCALAPPDATA%\TaishenIME 并 regsvr32 注册
