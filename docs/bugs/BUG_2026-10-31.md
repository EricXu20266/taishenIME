# BUG 2026-10-31

## BUG-2026-10-31-01：IMM32 版输入法导致 winlogon 崩溃，微软账户无限登录循环

**严重级别**：P0（系统无法登录，安全模式同样失效）

**影响版本**：2026-10-31 15:20:50 写入的 imm32 构建（`taishen_ime_imm32.ime`，3,708,416 字节；
同批 `taishen_ime.dll` 6,811,136 字节）

**影响范围**：安装该键盘布局且用户预加载列表含 `e0c00804` 的账户。本机仅 `jerry` 命中，
`Admin` 不受影响。

**结论**：这不是输入功能缺陷，是**加载/卸载时序缺陷**。该构建在 winlogon 进程内被加载，
模块卸载后仍留有回调，回调访问已释放内存（use-after-free）→ winlogon 崩溃 → 登录会话销毁
→ 返回登录界面 → 循环。

---

## 现象

- 微软账户 `jerry` 输入 PIN 后显示「欢迎」，转圈数秒，直接弹回登录界面，无限循环。
- 安全模式下同样无法登录。
- 本地账户 `Admin` 登录正常。
- 事件日志中 **没有** 用户配置文件加载失败（User Profile Service 无 1500/1515 事件），
  每次 profile 都成功加载 —— 排除 profile 损坏这一常见猜测。

## 根因分析

1. **加载**：winlogon/LogonUI 在登录会话建立与切换阶段，按
   `HKLM\...\Keyboard Layouts\E0C00804` + 用户 `Preload` 加载 IMM32 输入法，
   即 `LoadLibrary(taishen_ime_imm32.ime)`。
2. **执行**：该构建在 DllMain、窗口过程或全局 hook 上注册了回调。
3. **卸载**：登录完成、会话切换或 IME 实例释放时，系统 `FreeLibrary` 卸载模块。
4. **悬空**：已卸载模块的回调仍被 winlogon 调用 → 访问已释放内存 → `0xc0000005`。
5. **后果**：winlogon 是登录会话的父进程，崩溃即会话销毁 → 回到登录界面。

**为什么安全模式也失败**：布局注册在系统级 `HKLM`，预加载项在用户配置里，安全模式
同样处理这两处，因此照样加载、照样崩。这不是两个独立故障。

**为什么函数签名层面看不出问题**：IMM32 的 `ImeInquire` / `ImeSelect` / `ImeProcessKey`
在普通应用里调用正常（升级后用户在重启前还正常打过字），缺陷只在「宿主进程卸载模块后
仍有回调」这一时序下暴露。winlogon 的模块生命周期与普通应用不同，是这个 bug 的放大器。

## 处置（本机已执行并验证）

备份目录：`C:\Users\Admin\.taishen\backups\jerry-login-fix-20261031\`

```
keyboard-layout-E0C00804.reg    ctf-tip.reg    clsid.reg
ctf-tip-wow64.reg               jerry-preload.reg
taishen_ime_imm32.ime           （崩溃版本的原始文件）
```

处置步骤（管理员权限，在可登录的 Admin 会话下执行）：

```powershell
# 1. 删除系统级 IMM32 键盘布局入口
Remove-Item 'HKLM:\SYSTEM\CurrentControlSet\Control\Keyboard Layouts\E0C00804' -Recurse -Force

# 2. 移除 jerry 预加载列表第 3 项（e0c00804）
Remove-ItemProperty 'Registry::HKEY_USERS\S-1-5-21-...-1001\Keyboard Layout\Preload' -Name '3' -Force

# 3. 停用 crashing 文件（防止任何残留加载点再次加载）
Move-Item 'C:\Users\jerry\AppData\Local\TaishenIME\taishen_ime_imm32.ime' `
          'C:\Users\jerry\AppData\Local\TaishenIME\taishen_ime_imm32.ime.blocked-20261031'
```

**保留**：TSF 注册（`CTF\TIP` / `CLSID` / WOW6432Node 镜像）与 `taishen_ime.dll` 未动。
处置只摘掉出问题的 IMM32 兼容层，TSF 输入法继续可用。

**回退**：导入备份目录下 5 个 `.reg`，并把 `.blocked-20261031` 改回原名。

## 开发侧改进建议

1. **安装位置与注册层级必须一致（P0）**
   不做系统级 `HKLM\Keyboard Layouts` 注册，或把文件装到 `C:\Program Files\`。
   当前形态等于让登录界面去加载一个只属于某个用户目录的文件，路径可用性、
   权限与会话上下文全都不可控。

2. **模块卸载路径必须清空所有回调（P0）**
   排查 DllMain 之外的注册点：`SetWindowsHookEx`、子类化窗口过程、CTF/TSF 回调、
   定时器、线程池回调。`FreeLibrary` 前必须有对称的反注册，且反注册失败要能被观测到。

3. **升级器需要热替换防护（P1）**
   覆盖已被 winlogon/LogonUI 持有的 `.ime` 前，应：先注销 IME → 提示重启 →
   写入新文件名并切换注册（原子替换），失败可回滚。当前直接覆写等于把登录进程
   推向一个未验证的新二进制。

4. **暴露面最小化（P1）**
   IMM32 兼容层建议只做转发（委托给 TSF 或引擎进程），不在自身内部持有窗口/hook；
   或仅在用户会话内注册，不进入登录界面可见范围。

5. **升级后自检（P2）**
   安装器或托盘在升级后检测 `winlogon.exe` / `LogonUI.exe` 是否加载了旧模块，
   命中则拒绝完成升级并提示重启。

6. **发布前增加登录界面回归（P2）**
   在干净用户上做一次「注销 → 用该用户登录」的冒烟测试，覆盖安全模式。

## 教训

系统级输入法的失败面不是「打字打不出来」，而是「登录不进去」。

任何进入 `HKLM\Keyboard Layouts` 的组件，都要按「会被 winlogon 加载」的假设设计：
无用户目录依赖、无卸载残留、可原子替换、失败可降级。

## 修复（0.1.70）

### 版本结论

**不是 0.1.69 引入。** IMM32 系统级注册随 2026-08-09 的 IMM32 兼容层（`f9b3894`）一起进入，
GitHub 上所有 release（`v0.1.51` — `v0.1.69`）都含它。`git diff v0.1.68 v0.1.69 -- platform/`
为空，两层源码完全一致；0.1.69 只是换了引擎二进制，并恰好在重启后第一次让登录界面加载它。

### 直接死因（比原报告更精确）

`engine_init` → `dictionary::init` 会 `std::thread::spawn` 一个 detached 词库加载线程
（`engine/src/dictionary/mod.rs:3301`）。winlogon 登录完成后 `FreeLibrary` 卸载模块，
线程仍在执行已卸载代码 → `0xc0000005`。另外 `RegisterClassW` 注册的 IME 窗口类从未注销，
`DllMain(DLL_PROCESS_DETACH)` 还调用了候选窗 `Hide()`。三者叠加，`_unloaded` 后缀与此吻合。

### 代码修复

| 层 | 改动 |
|----|------|
| `platform/windows/src/imm32/imm32_ime.cpp` | 新增 `IsSystemLogonHost()`（winlogon/LogonUI/consent/csrss/smss/services）；`ImeInquire` 直接返回 FALSE，其余导出全部短路，登录宿主不初始化引擎、不注册窗口类 |
| 同上 | `DllMain` ATTACH 调 `DisableThreadLibraryCalls`；DETACH 不再调用任何 UI |
| 同上 | 候选窗改为 `CandWin()` 惰性 `new` + 永不析构，避免静态析构在 loader lock 内销毁窗口 |
| `install/install.nsi` | 安装开始先 `RemoveLegacyImeRegistration`（校验 `Layout File` 含 `taishen_ime_imm32` 后删 HKLM 键 + Substitutes）；删除 3b 段的 `regsvr32` / `ImmInstallIME`；卸载段补兜底清理；随包安装 3 个开关/救援脚本 |
| `install/install.ps1` / `install_latest.ps1` | 同样不再自动注册，安装前清理历史注册 |
| `install/enable-imm32.ps1` | 新增：管理员手动启用老游戏兼容层（regsvr32 + ImmInstallIME） |
| `install/disable-imm32.ps1` | 新增：删 HKLM 注册 + 重建各用户 Preload（过滤 e0c00804） |
| `install/fix-login-loop.ps1` | 新增：登录循环救援脚本，可从另一个管理员账户运行 |

### 已安装历史版本的用户（≤ 0.1.68）

- **能正常登录**：直接安装 0.1.70，安装器会先摘掉旧注册，重启后登录界面不再加载 IMM32。
- **已陷入登录循环**：用另一个管理员账户（如本机 `Admin`）运行 `fix-login-loop.ps1`，
  或手动删除 `HKLM\SYSTEM\CurrentControlSet\Control\Keyboard Layouts\E0C00804`。
  删掉该键后，用户 Preload 里的 `e0c00804` 因找不到布局被系统忽略，无需逐个用户清理。
- **没有第二个管理员账户**：用 Windows 安装介质启动，命令提示符执行 `reg delete` 删同一路径。
- **不要指望安全模式**：布局注册在 HKLM、预加载在用户 hive，安全模式同样处理这两处。
