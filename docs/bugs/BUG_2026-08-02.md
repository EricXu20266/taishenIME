# Bug 修复记录 — 2026-08-02

## BUG-2026-08-02-01: 切换输入法宿主程序崩溃（0xc000041d）

**现象**：切换到泰深输入法时，宿主程序（notepad++ / explorer / 泰深.exe）崩溃。
事件日志：错误模块 `taishen_ime.dll`，异常代码 `0xc000041d`
（STATUS_FATAL_USER_CALLBACK_EXCEPTION，回调内未处理异常），
三个宿主崩溃偏移全部指向 `taishen::CandidateTheme::CandidateTheme` / `Default`。

**根因**：`config_reader.h` 中 `CandidateTheme` **构造函数死递归**：

```cpp
CandidateTheme() { *this = Default(); }   // 构造 → 调 Default()
static CandidateTheme Default() {
    CandidateTheme t;                     // Default() 内构造局部对象 → 又调构造 → 无限递归
    ...
}
```

每次构造 `CandidateTheme`（TSF CoCreateInstance 构造 CTextService → 候选窗口
m_theme 初始化；LoadConfig 构造 ImeConfig → theme 成员）都触发无限递归 → 栈溢出。
TSF CoCreateInstance 处于系统回调上下文，栈溢出被包装为 `0xc000041d`；
独立 exe 测试直接报 `0xc00000fd`（栈溢出）。

**引入时机**：V0.2.4 皮肤主题（0.1.22）——0.1.22/0.1.23/0.1.24 三个版本均带此 bug。

**修复**（config_reader.h）：默认构造函数改为初始化列表直接赋值四色，
`Default()` 返回 `CandidateTheme()`，切断递归。

**验证**：
- `test_config_reader.exe`：之前崩溃（0xc00000fd），修复后 PASSED
- `test_tsf_load.exe`：之前通过注册表加载旧 DLL 崩溃，修复后 CoCreateInstance PASSED
- 三个冒烟测试 + cargo 单测全过

## BUG-2026-08-02-02: build_vs18.bat 冒烟测试错误检查失效

**现象**：test_tsf_load/test_config_reader 栈溢出崩溃（退出码 0xC00000FD，
cmd 有符号解释为负数），但脚本显示 "ALL BUILD + TESTS PASSED"。

**根因**：`if errorlevel 1 goto :err_test` 只在 errorlevel >= 1 时成立；
崩溃码 `0xC00000FD` 被 cmd 解释为 `-1073741571`（负数 < 1）→ 检查漏过。

**修复**：改为 `if not "%errorlevel%"=="0" goto :err_test`。

**验证**：修复后崩溃进程会正确触发 `[ERROR] Smoke test failed` 退出。
