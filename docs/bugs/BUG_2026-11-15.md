# BUG 2026-11-15

## BUG-2026-11-15-01：魔兽世界组词时拼音漏进输入框、翻页无组合区、长词选不到

**严重级别**：P1（游戏内组词完全不可用，且会往聊天框写入拼音）

**发现方式**：Eric 在魔兽世界中输入 `moshoushijizhenhaowan`，逐字选词时
输入框出现「天qi'zhen'hao气zhen'hao真hao好」这类内容；翻页后组合区空白；
期望的「魔兽世界」始终选不到。

**影响范围**：所有不渲染 TSF 组合属性的宿主（GFx 自绘引擎类游戏，
魔兽世界经 msctfscape 桥接实测复现）。普通应用（记事本 / 浏览器 / 微信）不受影响。

---

## 现象

| 序号 | 现象 | 复现输入 |
|------|------|----------|
| 1 | 选完第一个字后，剩余拼音被当正文插入 | `tianqizhenhao` → 选「天」→ 输入框出现 `天qi'zhen'hao` |
| 2 | 每次选字都重复一次「已选字 + 剩余拼音」 | `天qi'zhen'hao` → `气zhen'hao` → `真hao` → `好` |
| 3 | 翻页后编辑区没有组合串，候选窗也可能看不到内容 | 组词中按 PgDn / +/- |
| 4 | 一翻页就掉进逐字模式，长词永远选不到 | `moshoushijizhenhaowan` 只有 2 页候选，翻第 2 次即进组词 |

## 根因（三条，各自独立）

### 1. `inline_preedit` 开关只接了候选窗，没接应用文档

- 候选窗侧：`candidate_window.cpp:127` 用 `!m_inlinePreedit` 决定画不画拼音行 ✅
- TSF 侧：`tsf_module.cpp:2088` 无条件把拼音写进 composition ❌
- IMM32 侧：`imm32_ime.cpp:578` 无条件写 `GCS_COMPSTR` ❌

于是关掉 `inline_preedit` 也拦不住拼音进文档。

魔兽世界不渲染 TSF 组合属性，`StartComposition("qi'zhen'hao")` 的 `SetText`
被当成正文插入。日志实证：`ReplaceCompositionText: len=5 text=shi'b`
（带音节分隔符，只有 `syllable_display()` 会产出这种串）。

### 2. 组词中间选字用「Commit + Start 剩余音节」

`tsf_module.cpp:2143` / `2583` 在组词中间音节选字后调用
`Op::Start` 重新开组合并写入剩余音节。宿主若把组合当正文，
第 2 次、第 3 次选字就会继续插入拼音。

### 3. 引擎翻到候选末尾就强制进组词，且组词只出单字

- `engine/src/lib.rs` `page()`：`if self.page_advances >= 3 || at_boundary`
  ——候选只有 1-2 页时，翻一次翻不动就进组词。
- `apply_mode(Mode::Compose)`：候选硬过滤 `chars().count() == 1`，只出单字。

用户还没浏览完候选就被拽进逐字模式，而逐字模式本身也出不了长词。

## 修复

### A. 行内预编辑贯通到文档组合串

新增 `AppStateInlinePreeditEnabled(cfg)` / `AppStateInlinePreeditForProcess(cfg, proc)`：

判定顺序 `app_inline`（强制开）> `app_no_inline`（强制关）>
出厂兼容表（`wow.exe`）> 全局 `inline_preedit`。

| 文件 | 改动 |
|------|------|
| `include/config_reader.h` | 新增 `app_no_inline_list` |
| `src/config_reader.cpp` | 解析 / 写回 `app_no_inline=` |
| `include/app_state.h` | 两个判断函数声明 |
| `src/app_state.cpp` | 出厂表 `kBuiltinNoInline = {wow.exe}` + 判定实现 |
| `src/tsf_module.cpp` | 组合串只在 `inlinePreedit` 为真时写入；组词中间音节不再 Start 剩余拼音；候选窗 `SetInlinePreedit` 与文档同源 |
| `src/imm32/imm32_ime.cpp` | 新增 `g_inlinePreedit` 与 `GetSelfProcessName()`；组合串恒空 |

### B. 组词触发与候选

- `page()`：删掉 `at_boundary` 单次触发，只保留累计 3 次翻页。
- `apply_mode(Mode::Compose)`：候选改为
  `phrase_group_guess(剩余拼音)` 的整句/整词（优先）+ `query(当前音节)` 的词条与单字（兜底）。
- `select_candidate`：组词候选按字符数推进音节（选「魔兽世界」一次走完 4 个音节）。

## 第二轮：候选窗被自己的兜底判据藏掉（同日 14:10）

第一次修复后 Eric 实测：拼音不再漏进输入框，但「翻页后屏上没内容」依旧。

**日志证据**（Wow PID 22224，`ime_debug.log`）：

- 全程无 `ReplaceCompositionText` → 拼音污染已修好
- 有 `UpdateCandidateWindow: UpdateUIElement`，但**没有** `pinyin=... cands=...`
  → 在 `UpdateCandidateWindow` 的自绘兜底分支提前 `return`

**根因**：`msctfime` 桥接会替游戏读一次候选数据（`GetCount`/`GetString`），
把 `m_uiElementDataRead` 置 1。`AppStateShouldSelfDrawWhenSuppressed` 的自动判据
「宿主读过数据 = 它会自己画」因此判 true → `CandWin().Hide()` → 用户看不到任何候选。
而 Wow 是自绘引擎，实际并不画。

**修复**：新增出厂强制自绘表 `kBuiltinSelfDraw = { wow.exe }`，
优先级 `app_self_draw` > `app_no_self_draw` > 出厂表 > 自动判据。
