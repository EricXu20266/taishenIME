# BUG 2026-11-09

## BUG-2026-11-09-01：隔音歧义词全部被埋（「预案」打不出、无法组词）

**严重级别**：P1（常用词完全不可达，用户无法通过任何输入路径打出）

**发现方式**：Eric 手动输入 `yuan` 想打「预案」，词库无该候选，翻页与组词均不可用。

**影响范围**：`system_dict.db` 372,733 条中 **695 个词**。它们都满足「拼音连写后
最长切分音节数 < 汉字数」，即词库注音丢掉了音节边界，词被当成单音节输入处理。
典型：预案、西安、提案、立案、饥饿、余额、图案、巨额、彼岸、里昂、吉安、酷爱、
迪奥、堤岸、书案、企鹅、湖岸、绿萼、激昂、西安事变、信息安全。

---

## 现象

以 `yuan` 输入为例（修复前实测）：

| 输入 | 目标词 | 修复前位置 | 组词模式 |
|------|--------|------------|----------|
| yuan | 预案 | 第 34 位（第 7 页） | 不可进入 |
| xian | 西安 | **完全不在 40 条候选内** | 不可进入 |
| tian | 提案 | 第 15 位（第 3 页） | 不可进入 |
| fangan | 方案 | 第 1 位（正常） | 可进入 |

`xian` 键共 58 条词条，候选上限 `page_size(5) × max_pages(8) = 40`，西安被挤出后
在用户侧等于「词库里没有这个词」。

## 根因（三层，缺一不可）

### 1. 词库注音丢掉音节边界（根源）

`taishen-dict` 用 pypinyin 取音节列表后直接 join：

- `sources/jieba.py:77` → `py_joined = "".join(s[0] for s in syls if s)`
- `sources/wiki.py:141` → 同样写法

`yu` + `an` 变成 `yuan`，`xi` + `an` 变成 `xian`。于是「预案」与「元/原/远/院」
共用一个索引键，「西安」与「先/现/线/县」共用一个索引键。

### 2. 引擎只按最长切分判断音节数

`engine/src/lib.rs` 的 `complete_syllable_count` 调 `split_first_syllable`
（最长音节优先），`yuan` 得到 1 音节。`apply_word_len_match` 据此把
「字数 == 1」判为匹配档、2 字词判为「超长词」压到最后。

### 3. 组词模式只走单一切分

`split_compose_syllables` 同样只产出最长切分路径。`yuan` 只有 1 段，
不满足「≥2 段」门槛 → 组词模式完全不触发，用户连逐字选「预」+「案」都不行。

### 4. 同键词频竞争加剧

词库词频按语料排名给出，单字天然靠前：`yuan` 键前 20 名全是单字
（元 3750 → 沅 2118），「预案」2106 排第 21。词长分区 + 候选截断后彻底不可达。

## 修复（引擎侧，V0.6）

### 1. 新增多路径切分 API

`engine/src/pinyin/mod.rs` 新增 `syllable_split_variants(input, limit)`：
DFS 枚举全部完整音节切分，长音节优先展开。`yuan` → `[yuan]` 与 `[yu, an]`。

### 2. 词长分区改用音节数集合

`engine/src/lib.rs` 新增 `complete_syllable_counts`（升序去重）。
`apply_word_len_match` 的分区判据由「字数 == 单一 n」改为「字数 ∈ 可行音节数集合」。
`yuan` 的集合是 `{1, 2}`，单字与「预案」同为第一档，不再被压后。

### 3. 隔音歧义候选提升

新增 `apply_ambiguous_split_boost`：当输入同时存在单音节切分与多音节切分
（`counts[0] == 1 && counts.last() > 1`）时，把候选里「汉字数 == 多音节切分段数」
的词提到第一页末位（第 5 位，只提 1 个）。无歧义的输入（fangan/zhongguo/nihao）
完全不受影响。

### 4. 组词模式多路径选择

新增 `ambiguous_compose_split`：当整串可作单音节且词库确有与该多音节切分对齐的
词条时，按多音节路径组词。`yuan` → `[yu, an]`，`xian` → `[xi, an]`，
`tian` → `[ti, an]`；`xianzai` 这类无单音节解释的输入保持原逻辑。

## 验证（修复后实测）

| 输入 | 目标词 | 位置 | 组词模式 | 首音节 |
|------|--------|------|----------|--------|
| yuan | 预案 | 第 5 位（第一页） | 可进入 | yu |
| xian | 西安 | 第 5 位（第一页） | 可进入 | xi |
| tian | 提案 | 第 5 位（第一页） | 可进入 | ti |
| fangan | 方案 | 第 1 位（不变） | 可进入 | fang |

组词全链路实测：`yuan` → 翻页选「预」→ 第二段候选 `按/案/安/暗/氨` → 选「案」
→ 完成并 learn(`yuan`, `预案`)。

回归：`cargo test --lib -- --test-threads=1` 365 通过 / 0 失败。
注意必须加 `--test-threads=1`：并行跑会因共享词库状态产生 3 个假失败
（debug_bru_zhyang_hotword / test_delete_user_word_short_pinyin /
test_single_letter_no_phrases），与本次改动无关。

## 待办（词库侧，下一步）

引擎修复用「汉字数」作为正确音节数的代理，能覆盖纯汉字词；彻底方案是让词库
保留真实音节边界：

1. `taishen-dict/sources/jieba.py`、`wiki.py`：注音改为 `"'".join(...)`（`yu'an`）。
2. `system_dict.db` 增加 `syl` 列（音节数），或由 pinyin 分隔符推导。
3. 引擎索引元组扩展音节数、`.bin` 格式升版本（v4），查询端用真实边界替代
   汉字数启发式。可正确处理「花儿」这类汉字数 ≠ 音节数的词。
4. 重建 `system_dict.db.bin`（约 179 MB）与 `domains.db.bin`。

完整受影响词清单：`sessions/86aa6a65/outputs/隔音歧义词清单.md`（695 条）。
