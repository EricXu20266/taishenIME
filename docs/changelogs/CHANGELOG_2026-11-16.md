# CHANGELOG 2026-11-16

## 长句整句解码：词图 Viterbi + 束搜索接入普通输入流

### 现象

连续输入整句拼音时，候选要么完全不出来，要么首位是明显错误的分词：

| 输入 | 修复前首位 | 应有 |
|------|-----------|------|
| `nimenjigerenzaizheli` | 你们几个**认栽**这里 | 你们几个人在这里 |
| `nimenjigezaizheli` | 你们几个**再者里** | 你们几个在这里 |
| `nimenjigezaizheliganshenme`（25 字符） | **0 个候选** | 你们几个在这里干什么 |

### 根因

1. **长句靠 DFS 拆段，不是词图最优路径**：`phrase_group_guess` 按「先到先得」展开，
   输出预算 512 条满了就丢弃后续所有分支，正确路径经常根本没被探索到。
2. **段数上限 5、每段候选 2-3 个**：「你们 / 几个 / 人 / 在 / 这里」需要 5 段，
   正确的切分依赖「这里」这个候选进格，挤掉就没了。
3. **排序第一优先级是「段数少」**：「几个认栽」（2 音节凑成低频词）压过「几个人 / 在」。
4. **输入长度上限 24 字符**：25 字符的整句直接返回空。
5. **最终过滤无条件删除 >10 字候选**：整句即使算出来也被杀掉。
6. **搭配表稀疏**：40 万对里 98.6% 计数为 1，无法作为主要排序依据。

### 改动

- **新增 `engine/src/sentence.rs`**：语音节图上的 Viterbi + 束搜索。
  - 格子 = 连续 k 个音节（k ≤ 8）命中的词，取自完整拼音索引（用户词 / 常用词 /
    系统词 / 领域词四层）。
  - 打分 = 词频按词数折算 + 相邻词搭配档位 + 用户词加成 − 低频词扣分。
  - 束宽 8，输出前 3 条不同文本的整句。
  - 音节边界歧义（`xian` = `xian` / `xi+an`）分别求路径再合并排序。
- **容错切分**：整串读不通时才启用（能完整读成拼音就按原样读，不走编辑），
  支持单字符替换（打错）、音节删除/插入（漏打）、跳过单字符（多打），
  每处编辑带代价，总计 ≤3 处。递归带节点预算，防长串指数展开。
- **接入普通输入流**（`engine/src/lib.rs`）：输入 ≥8 字符、非英文单词时，
  整句候选插到候选最前，最多 3 条；已存在同文本的词级候选移到首位并标记来源。
- **`Source::Sentence`**：整句候选不受「>10 字过滤」限制，也不写进用户词学习。
- **`dictionary::span_candidates`**：整句格子专用查询。常用词表的第三字段是人工
  rank 而非词频，统一折算成系统层同名词的真实词频——否则「在 / 再 / 载」被拉平，
  同音字分不出高下；候选按词频排序后再截断，避免常用词表排名靠后的高频词被挤出。
- **格子缓存**：`span_candidates` 结果跨按键缓存（按键增量，前缀格子可复用），
  词库/用户词变更时整体清空。

### 已知限制

- 同音词歧义仍受词库词频偏差影响：`womenxiangquchifan` 首位是「我们想曲吃饭」，
  正确解在第 3。根因是书面语词频里「相去 / 想曲」这类词条不弱，需要更高质量的
  口语搭配统计。
- 缩写输入（`nimjige` 的 `m` 代表「们」）暂不支持：简拼槽需要「词首字母」查询，
  当前只做漏打/多打/打错的音节级容错，`nimjige` 会读成「你米格人」。

### 性能

整串输入累计耗时（release，含每次按键重算）：

| 输入长度 | 累计 |
|---------|------|
| 13 字符（`nimenjigezaizheli`） | ~85ms |
| 20 字符（`womenzaizheliganshenme`） | ~90ms |
| 25 字符（`nimenjigezaizheliganshenme`） | ~300ms |

平均每键 4-12ms。主要开销是搭配表逐次查询（每次取锁），
后续可改为「一次取锁批量查」进一步压缩。

## 审计修复（同日）

独立审计提出 1 个 P0、5 个 P1，均已修：

- **P0** 大词库异步换入、领域库合并后不清整句格子缓存 → 启动初期用内置词库算出的
  结果被长期复用。现在换库与合并时清空。
- **P1** 整句上屏仍写 `last_committed` 与搭配学习（并落盘）→ 每次整句写一条
  「前词 → 25 字串」的垃圾搭配，且下一次整句的前文变成整句本身。已排除。
- **P1** 删除用户词 / 切换用户词库 / 清空用户词后不清缓存 → 删掉的词继续在整句里胜出。已补。
- **P1** 整句与词级候选同文本时改写了来源 → 「中国」这类普通词条被错标为整句，
  跳过学习与上下文记录。改为只挪位置、保留原来源。
- **P1** 容错切分每段把音节候选算了两遍 → 改为每段算一次，再按代价分两轮展开。
- **P2** 切分深度按 30 音节前置截断，超长输入不再白算。
- **P2** 探针分开统计「候选首位命中」与「整句解码命中」，验收不再依赖词级候选碰巧命中。

## 常用词库：泰深语料挖掘补入 235 条（词 104 / 口语短语 131）

### 数据源（自家库，非外部）

### 清洗

去 ``` 代码块、Markdown 表格行、Windows/Unix 路径、URL、HTML 标签、≥4 字符拉丁串，
只保留中文与常用标点：**36.62M → 12.87M 字（保留 35%）**，7 个分片。

### 方法（两步）

**第一步（失败方案，记录在案）**：直接做字符级 n-gram（2-4 字）。
未登录候选 2 字 14 万 / 3 字 36 万 / 4 字 31 万，但 top 全是跨词边界碎片
（`户说` 来自「用户说」、`览器` 来自「浏览器」）。此路不通。

**第二步（采用）**：词库最大匹配分词 + 词序列组合统计。
- 词库 49.8 万词（system 37.3 万 + domains 17.3 万 + common 去重）
- Trie 正向最大匹配 → 1290 万字切成 484 万词
- 统计连续 2-4 词的组合（长度 3-12 字），freq ≥ 2 剪枝
- 得到组合候选 40.9 万条，天然不跨词边界

### 筛选取舍

规则粗筛（去掉「的/了/着」开头结尾、连续同字、长度越界）后人工逐条判定。

**取舍标准**：只收语义独立的词 / 术语 / 短语，**不收纯句法组合**。
`先看`、`再跑`、`现在写`、`直接改`、`会覆盖`、`同时读` 这类全部剔除——
它们是「副词 + 动词」的句法搭配，交给 `sentence.rs` 的 Viterbi 解码，
进常用词库只会膨胀候选。

剔除的代表性噪声：

| 类型 | 样例 |
|------|------|
| 跨词碎片 | 个文件、文档里、代码里、文件是、前加、里写 |
| 句法组合 | 现在写、直接跑、然后改、会显示、同时查 |
| 量词开头 | 个交易日、个板 |
| 同音冲突 | 主歌（与「逐个」同全拼） |
